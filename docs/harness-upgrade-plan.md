## 1. 铁律（每一批都适用）

1. **先能看见，再动手。** 没有数的改动无法证明有效，也无法回退判断。
2. **能用代码判准的，不交给模型。**（`checks/__init__.py` 的老规矩）
3. **判据宁可窄一点**，误伤比漏报贵；阈值一律在**真实产出**上量，不拍脑袋。
4. **闸跑绿不等于闸有用**——每条新判据都要**突变验**（把修复撤掉必须变红）。
   *突变没被抓住时，先怀疑用例不够，别以为是实现对。*
5. **不改 `loop.py` 的循环结构。** 全部落在 middleware / checks / tools / prompts / 落库。
6. **每一批跑全量闸**：后端 `pytest -q`、前端 `npm test`。
7. **质量优先于省钱。** 任何一条让产出变差，退回去。

## 4. 不做

- 不换 memory engine（**就用 kite**）。
- 不引入 DSPy / GEPA / Mem0 / Letta / WritingBench 任何一个当依赖——要的是判据形态，不是运行时。
- 不加新评分维度（已有 25 个；问题在执行器和上下文，不在指标）。
- 不做自动删重复、不做跨跑自动回滚（只报，不替用户决定）。
- 不上 token 级控制器（走 HTTP 接口，没有解码控制权）。
- 不为「写得更长」优化（LongWriter 那条线的目标跟我们正相反）。
- 不按 LoCoMo 那类基准选型（2026 年已饱和到塞满上下文就能拿分）。
