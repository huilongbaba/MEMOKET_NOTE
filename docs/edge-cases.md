九种条件（计划 §1.3）：**空输入**（有输入框的动作，什么都不写就确认）· **空正文**（整篇一个字没有）·
**无选区**（作用在选区上的动作，没选任何字）· **无知识库**（这个用户 0 条事实）·
**离线**（后端起着，模型服务连不上——分「拒绝连接」和「黑洞」两种，黑洞 = 主机不回包，实拍 `192.168.77.8` 关机就是这样）·
**后端没起来**（浏览器连不上后端：进程没在跑 / 刚重启）· **模型报错**（模型服务回 4xx / 5xx）·
**超时**（模型收下请求不回）· **重复点击**（连点两下 / 跑的过程中再点）。
**P32 加了第十种**：**模型答得不合形状**（200 + 脏内容，不是 4xx/5xx 也不是不回）——
它在下面那几张九列表里**没有列**，单独写在文末「P32 补」和「P35 补」那两节，别在这儿找
（P32 立了这一列并填了 AI 组 + `custom`，**P35 把剩下那七个 `？` 摆完了**：右键五项 + harness 两条）。

怎么摆这九种条件（都不碰真库，全在 `KITE_DATA_DIR` 指向的 scratch 拷贝上，见文末）：
空输入 / 空正文 / 无选区 用探针摆；无知识库 换一个没有 KB 的用户；**离线 / 模型报错 / 超时 用一个假模型服务**
（`fakellm.py`：`/ok`、`/err500`、`/err401`、`/hang` 四种模式 + 假语音服务两种），把 scratch 库的供应商地址指过去；
黑洞用真关机的 `192.168.77.8`；拒绝连接用 `127.0.0.1:1`；**后端没起来** 用 `netdown` 探针把页面里的 `fetch`
换成一律 `Failed to fetch`（跟后端进程死掉时浏览器看到的一模一样）。

三条横跨全表的结论（本批修了前两条）：

1. **后端没起来 ≠ 模型连不上**。原来两种都翻成「模型连不上——去设置里检查 LLM 供应商」；后端进程没起来时这是指错了地方。
   现在 `Failed to fetch` 单独说「连不上应用后台（后端进程没在跑，或刚重启还没起来）」，不带「打开设置」。
2. **明知模型不可达还照发请求**。状态栏红着写「LLM 不可达」，每个要模型的按钮照样发请求、转到连接超时才报错
   （黑洞主机下是操作系统 SYN 重试的 75 秒+）。现在：前端先看健康检查，红着就拦（带「打开设置」）；
   后端把**连接**超时单独收到 10 秒（读超时不动，本地模型算得久是正常的）。
3. **非流式动作没有「停止」**（校验 / 重写 / 润色 / 扩展 / 来龙去脉 / 骨架 / 排版 / 幻灯片）：模型卡住要干等 300 秒。
   P3 给右键菜单五项和幻灯片加了停止；**骨架 / 智能排版 P9 补上**（`p9-skeleton-hang-after` / `p9-restructure-hang-after`）。
   P9 顺手把第四条也修了：**「停止」只撤块、请求照跑、跑完仍插进正文**（图片转表格 / 语音输入 / 插入音频 / 录音钮）——
   实拍是真的（停了之后表格 / 文字照样插进来），全部挂上 AbortController；「⋯ 存入知识库」的后台 job 接上了本来就有的 cancel。

### 2. `/` 那一下留在正文里：**判下来不是缺陷**（P44 #6 / P47 #1，连着三批「照旧」）

这一批**先判再动**，判下来**不是缺陷，代码零改动**：

* **Esc 的意思是「关掉这个菜单」，不是「撤掉我刚打的字」。** 撤字有 ⌘Z，那是用户自己按的、
  可预期的一条路；让一个关闭动作顺手删掉文档里的字符，正是这条线一路在修的那个形状
  （「不许静悄悄替他做决定」，P39 / P41 #5 ② / P46 #3）。
* **用户真的要打一个字面的 `/` 时，这是唯一的出路。** 这个仓自己就把「字面的斜杠」当过真事：
  `slashTypedAt` 只在行首 / 空白之后才认，「A/B 测试」「他/她」压根不弹菜单。
  而**行首**那个 `/`（「/ 表示根目录」）只能靠「弹出来再关掉」写出来——Esc 删字等于把它变成打不出来的字符。
* **外部依据（查到的那一侧）**：Obsidian 官方帮助写的是 “To exit the Slash command search
  without invoking a command, press `Esc` or the `Space` key.”，而论坛里「怎么打一个字面斜杠」
  的答案正是「打空格」——**退出之后那个 `/` 留着**，否则这条办法不成立。
  （**Notion 官方帮助对 Esc 一个字都没写，所以不拿 Notion 当依据**，不冒充查过。）
* 这个仓里本来就有同一条规则的另一半：`/` 后面打了空格又匹配不上任何东西时，
  菜单自己关掉、`/` 留着。**Esc 跟它是同一件事的两个按键，两边行为一致才是对的。**

处置：**代码不改**，`frontend/src/editor/__tests__/p49.test.ts` 5 条把这个决定钉住

> 通用说法：**「选不到 ≠ 没有」的镜像是「选到两个 ≠ 真有两个」。**
> 通配选择器（`[class*=…]`）既会漏也会多，而**多出来那一份长得跟真的一模一样**——
> 漏了是空数组，一眼可疑；多了是一段读起来像 bug 的证据，能在台账上躺两批。
> 判据里的元素一律用**真类名 + 直属关系**（`.toaster > .toast`），
> 并且**顺手钉住「容器只许有一个」**：那才把「真的渲染了两遍」这条路排除掉。

### 历史坏数据：说「这一段自相矛盾」，别说「这是旧版本采的」

屏幕活动某一天的「合计」可能荒唐地长（实拍「合计 20 小时 42 分钟」）：

**那句话不可知**：段里没有任何版本 / 写入方标记（盘上的键就那十个），

> 通用说法：**能用代码判准的就别交给猜。** 当「这条数据是哪一版产的」不可知时，
> 找一个**当场量得出来、跟版本无关**的等价判据。
> 另外**别在日级上判**：整天大部分样本是真的，坏的只压在少数几段上，

> （`st.facts` 是 `middleware/facts` 按工具调用填的），

### 摆一格系统事件：先做正向对照，再做要摆的那一格

macOS 上 Electron 的 `lock-screen` / `unlock-screen` 是观察
`NSDistributedNotificationCenter` 的 `com.apple.screenIsLocked` / `…Unlocked` 来的，
**分布式通知谁都能发**——所以「锁屏之后会怎样」摆得出来，不用动系统设置、屏幕一下都不用暗。

但**只摆要证明的那一格是不够的**：「发了 unlock，暂停还在」这句话有两种可能，
一种是产品对（`onPowerEvent('unlock', 'paused', autoPaused=false)` 回 `null`），
另一种是**那条通知根本没到这个实例**。两种在日志里长得一模一样。
所以顺序是：① 开到 `running` → 发 lock → **必须变 `paused`**（这一下证明监听是活的）
→ ② 发 unlock → **必须变回 `running`** → ③ 这才去摆「用户自己按的暂停 + unlock 不许解掉」。

> 通用说法：**一个只会打印 `false` 的探针当不了闸。** 摆系统事件那一类格子时，
> **正向对照跟要证明的那一格必须在同一个实例、同一趟里**；
> 而且那一步要会抛——否则把监听整条砍掉，它照样 EXIT=0。

### 「选不到 ≠ 没有」的第四张脸：**一个「多数时候是对的」默认参数**

> 只在少数那一次悄悄换了个对象。
> 判据里凡是有默认值的那一格，**要么让调用方必须给，要么把它读到的东西一起打出来**
> ——「读回 null」和「读的是谁的 null」是两件事。

### 一个根因写成一条，于是修了一半还是 `undefined`

P64 把「一键全删那一格读不到」的根因记成**一条**：钮叫「全部删掉」，

> 一个「什么都没读到」的格子往往不止一个原因——
> 修掉第一个之后**要再跑一遍**，别把「我知道原因了」当成「它好了」。
> 而且这一条在同一批里就有反证：`b4old` 用 `clickBtn`（先 `scrollIntoView`）量对了，
> **同一格有两份互相矛盾的读数时，先问「它们的读法差在哪」，再决定信哪一份。**

### 摘掉一项扫描名单，闸照样全过——**红不了不等于闸没了**

`check-greppable` 的扩展名名单里原来没有 `.mjs`，量具搬进仓库之后它看不见新来的那份。
补上之后要验这条闸真的管用，**直接把 `.mjs` 再摘掉是验不出来的**：
`.mjs` 里本来就没有 NUL，摘不摘它都绿。
得两步：**先埋一个真 NUL**（证明它真的在被扫、而且点名了那个文件），
**再摘名单**（证明同一个 NUL 就看不见了）。

> 通用说法：验一条「扫描范围」型的闸，反例得是**范围内才看得见的那个东西**。
> 只改范围不放东西进去，那一刀砍的是空气。
> 同族的还有两条：反例落在别的分支里（`copy_corpus` 两道核只砍一道）、
> 刀压根没进解释器（字节数一样 + `.pyc` 没清）。

### 双向同步：**防住了死循环，没防住「过期的回声盖掉新值」**

编辑器跟 React 是双向的：`content` 变了往 CodeMirror `dispatch` 一次；
CM 的文档变了通过 `onChange` 报回去、上层 `setContent`。
这两条路之间原来只有一道防护 —— 一个 `lastEmitted` ref：
回来的那一份跟自己刚发出去的一模一样，同步 effect 就不再 dispatch。
**那道防护治的是死循环，治不了顺序。**

智能续写流式写入时一秒钟几十次 `setContent`，而回声那一下 `onChange(旧文档)`
是**在同步 effect 里**发出来的 —— React 把它排在后面处理，
于是「刚到的那一片」被「上一片的回声」盖回去。盖回去之后
`content === lastEmitted`，同步 effect 从此一路 skip：**卡死在半截上**。
P68 实拍（打包壳 · 真 CM · 482 篇老用户库）：后端交出去并且已经 commit 进库的是 **1103 字**，
编辑器里只剩 **807**，1.5 秒后自动保存**把 807 写回了库**，把后端刚落的那一份盖掉；
同一屏上收工那行写着「+1060 字」、状态栏写着「763 字」。

三件事各记一条：

* **修法要窄**：不是「同步来的改动一律不回声」——CM 有可能在同一条事务上又改一道，
  那一份只有回声报得上去。所以标注里带上**发过去的那一份正文**，回来时**逐字比一次**：
  一模一样才当回声扔掉，不一样照报。
* **「两个数不一致」要先问「它们各自从哪条路来的」**：`liveContentRef` 不经 React、
  `content` 经 React —— 这一格里前者是对的、后者是坏的，而三批台账都默认了
  「界面上那个数错了」。**数没错，正文少了。**
* **两头一起错的时候，光比这两头是看不出来的**：编辑器 807、库也 807，
  只有跟**后端交出去那一份**比才露馅。「编辑器里没有 ≠ 库里没有」还有一条孪生：
  **编辑器和库一致，也不等于对**。

### 量它就会改变它：**探针每条发一次网络请求，把要查的竞态压没了**

同一条 bug，同一台壳，同一档假模型：**干净构建复现得出来，带探针的两趟都读回正常值**。
探针本身没写错 —— 它只是每记一条就 `api.clientLog` 一次（一次 fetch），
十几次网络调用把那个竞态窗口撑过去了。
换成**只往 `window.__p68` 推、跑完一次读走**（零网络包）之后，那个形状当场回来，
而且一次就给出了完整的时间线。

> 通用说法：查**时序 / 竞态**类的问题时，探针的成本必须接近零。
> 记日志走网络、走磁盘、走 `console` 的字符串拼接都可能是那根压垮竞态的稻草。
> 先在内存里攒，**一次读走**。
> 同族的还有一条反过来的：探针太重会让问题消失，而「问题消失了」
> 跟「问题修好了」在日志里长得一模一样。

### 闸拿整份文件 `includes` 判一个名字，**注释里那一份也算数**

P68 给走查驱动加了一条闸：「它读身份的键必须跟 `api.getUser()` 是同一个」，
实现是 `driverSource.includes("'memoket-note-user'")`。

> 通用说法：源码级的闸，判之前先把注释摘掉。
> 这是同一个形状的**第四次**（`check-css-classes` 顶上记着「注释」和 `url()` 两次，
> 加上这次）。
> 还有一条更要紧的推论：**「红不了」有时候就是「闸真的没了」**——
> 突变验里一刀没红，先别急着改预测，**先问这条闸是不是压根没在看那个东西**。

### 改一个「多数时候是对的」默认值，改的是默认值，不是 92 个调用点

P66 把 `d.noteId(user = 'terrence')` 这个坑核清楚之后留了一句「先量有多少处在裸调它」。
P68 量了：**92 处裸调 / 5 处带参**（6 批步骤脚本 + 公共驱动自己）。

或者把默认值换成**从这个窗口自己身上读**（改 1 处，92 处一起变对）。选了后者。

> 通用说法：一个错的默认值，**修默认值**；
> 「让每个调用方显式写出来」听上去更严谨，但它把一次修改摊成 92 次机会去漏。
> 配套两条：① 新的默认值要跟产品里那把尺子**同源**（照抄 `api.getUser()` 的两步，
> 不是「差不多一样」——另写一把就是下一次静默读空）；
> ② 读不出来时**抛**，别回落到另一个猜的值。
> 附带一条自嘲：写这一批的量具时，我自己在新脚本里把那个键写成了 `memoket.user`
> （真名是 `memoket-note-user`）——**同一个病当场又犯了一次**，靠的正是这条新闸点出来的。

### 一条「该报」的回声，报上去之后没人接，那它等于没报

P68 修好了「自己刚同步进去的那一份原样回声 → 盖掉新到的那片」，并且**特意留了一条活路**：
CM 有可能在同一条事务上又改一道，那一份**只有回声报得上去**，所以判据是「逐字相等才扔」。
P70 把这条活路走到底（真 React 19 + 真 CM 6，四格）：那条回声**确实报到了 React 的 `content`**，
**但 `liveContentRef` 没跟上**——而流式的下一片、轮末的服务端对齐、收工那行的字数、
`save()` 眼里的「服务端交了什么」，读的全是 `liveContentRef`。
下一片一到，从过期的镜像上算出来，CM 那一道**没了**。
更糟的一格：新片先进 React 的队列、回声排在后面，`content` 退回旧的那一份、
`content === lastEmitted` 之后同步 effect 一路 skip —— **跟 P68 实拍的卡死一模一样**。

> 通用说法：**「报上去了」不等于「被接住了」。** 一条报给 React 的值，
> 如果系统里真正的权威是另一个 ref，那这次上报只是把两份真相的分歧挪了个位置。
> 判一条上报路径修没修好，别只看「发出去了没有」，要问**收的那一头是谁、它更新了没有**。

### 治不了触发器就闸住触发器：把「今天有几个」钉成一条断言

P70 A 那一格量清楚之后，真正该问的不是「怎么修」，而是「今天有几个东西能触发它」。

没有一处在 `update()` 里对着同步事务动手。**所以那一格今天触发不了。**

> 通用说法：一个真实存在、但**今天没有触发器**的洞，最划算的处置常常是
> **把「触发器是 0」钉成一条会红的断言**，而不是现在就去改判据。
> 这样做的三个好处：① 不为一个不发生的事件收窄一条正确的判据；
> ② 哪天有人加了触发器，他会在自己那一刀上红一次，连带读到这段账；
> ③ 断言里**先断言分母**（「扫到的文件数 > 20」），否则目录读空了它永远是绿的。

### 「选不到 ≠ 没有」第五张脸：正则太紧，读回 `null` 而屏幕上写着

### 「选不到 ≠ 没有」第七张脸：**判据的字符类比产品窄**（引号那一版）

### **匹配上了 ≠ 匹配的是那一处**

`check-walkthrough-fakeshell.mts` 有一条「接线洞」断言：那条真跑的闸必须拿

> 通用说法：接线洞断言要**锚在调用点的形状上**（`spawn(process.execPath, [path.join(WALK, 'cdp.mjs')`），
> 不是「文件里提过这个名字」。**这条断言自己就是它要治的那个病的又一例。**

### **一条永远开不了火的反例不是反例**

> 通用说法：反例也要**证明自己开得了火**。判据挂在「某个输出里有没有某一行」上时，

### 注释也能把闸**误报成红**（`includes` 那一条的镜像）

### 「搬不搬进仓库」跟「搬进来跑不跑得了」是两件事

P66～P72 的 README 一直写着：`go.sh` / `launch.sh` / `fakellm*.py`

### 一个「0」得配一个非 0 才算数——**对照组不成立时要现造一个**

它落进后端日志才算「这条槽是通的」，那个 0 才说明得了什么。

> 通用说法：报一个「0 次」之前先问**「这条通道今天有东西说吗」**。
> 对照组不现成就现造一个，别把「没发生」和「没人在听」混成一句话。

### 「关掉」得是关掉，**不是拔电源**

P76 给假壳那条闸加第 ⑩ 步（关掉重开）时，第一版探路用 `kill -9` 收壳。

> 拔电源量出来的那一格会被记成产品缺陷，而产品那一侧什么都没错。
> 同族：**「点过了 ≠ 翻过了」**、**「换了一篇 ≠ 重开过一次」**。

### 「够不着」和「没接线」是两件事

假壳那条闸的文件头上有一整段「**够不着什么**」，写得很实：⑦ 选 vault 的系统对话框、
⑧ 的**采集**那一半、打包那一圈、后端重起——都要主进程或真打包，闸确实碰不到。
P78 照着这段话去找「够得着但没人接线的」，找到三处：

* **⑧ 的知情屏那一半**（`.journey-consent` / 两个钮 / 五条 facts /「留多久」那一行）
  —— 纯渲染进程 + 后端，`bnew.mjs` **每一趟都在打**，而 `PLAN` 里**一条判据都没有**；
* **⑨ ⌘K 只有一条 `项数 > 0`** —— 18 个去处掉成 1 个照样过；
* **走查第 ② 步整步没进 `PLAN`** —— `b1b.mjs` 早在仓库里、每批真走查都跑它，
  台账上 P43 #2 / P44 #4 的「✔」抄的正是它打出来的那一行，而 `npm test` 这一侧**是空的**。

> 通用说法：**一段诚实的「够不着什么」，久了会被读成「剩下的都接上了」。**
> 那段话只说明「这些碰不到」，它**不说明**碰得到的都接了判据。
> 每隔几批要反过来问一次：**打出来了却没人判的那几行，是哪几行？**

### 下限（`MIN_*`）挡得住「被砍」，挡不住「被调低」

`check-walkthrough-fakeshell.mts` 的 `MIN_STEPS`、`check-walkthrough-selectors.mts` 的
`MIN_CLASSES` / `MIN_SENDERS` 都写着「只准往上调」。P78 拿刀验了一次：
把 `MIN_STEPS` 从 8 改成 3，**闸没红**——下限对「步骤被砍掉」有牙，对「下限自己被调低」**没有牙**，
它靠的是有人读 diff 时看见那行注释。

> 通用说法：**一条靠注释生效的规矩，不是闸。** 下限是「扫不到东西的闸门会一直是绿的」的解药，
> 不是防篡改的锁。报「这条闸有下限」时，要连它挡不住什么一起报。

### 一篇里塞多段去量右栏：**读回来的可能是上一段的**

P78 想在一篇里连着量三条召回查询（五个段落），逐段点光标、逐段读右栏「记忆」。
**第 2 段读回来的「命中：」那一行跟第 1 段逐字相同**——右栏那一刻还没刷新。
同一趟五段的圆点 `落槽合计` 全是 0，而同一批 `recall64` 那一篇是 3，
说明这一篇的关系分析压根没落地。拆开成**一篇一条查询**重跑，读数才稳定、才跟上一批对得上。

> 通用说法：**「读回来一个数」不等于「量到了那一格」。**
> 连着量同一块 UI 的多个状态时，要有一条能分辨「刷新了」和「还是上一次那份」的判据
> ——两次读回来逐字相同，本身就是一条警报。
