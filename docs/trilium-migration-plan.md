# 150 轮改造计划：全面 Trilium 化

> 目标：界面结构、交互词汇、数据模型全部按 Trilium 来，**我们自己的功能
> 不是塞进去，是按它的语法重新表达一遍**。

## 0. 已经做完的（不占这 150 轮）

- Electron 外壳：自己拉后端、自己托管前端、崩溃也收得干净
- 数据模型：`branches` 表 + 克隆，文件夹不再是一种东西
- 旧数据迁移：文件夹变笔记，id 不变

## 1. 功能怎么翻译成 Trilium 的话

这张表是整个改造的判据。左边是我们现在的东西，右边是它在 Trilium 的
词汇里**本来就该待的位置**——不是找个地方塞进去。

| 我们的功能 | 现在长什么样 | Trilium 化之后 | 为什么是这儿 |
|---|---|---|---|
| 笔记列表 + 文件夹 | 侧栏两段 | **笔记树** | 任意层级、可克隆、拖拽、展开状态持久化 |
| 打开笔记 | 一次一篇 | **标签页 + 分屏** | 写作时要对照着另一篇写 |
| 大纲 | 中栏上方 | **右栏 · 目录** | Trilium 的 TOC 就在这儿 |
| 相关记忆 | 右侧固定栏 | **右栏 · 相关记忆** | 它是当前笔记的上下文，跟 TOC 同类 |
| Agent 运行面板 | 右侧固定栏 | **右栏 · 运行** | 对标它的 SidebarChat |
| 修订面板 | 右侧固定栏 | **右栏 · 修订** | 同上 |
| 写作骨架 | 右侧固定栏 | **ribbon · 骨架** | 它是**笔记的元数据**，正是 ribbon 的定位 |
| 知识库浏览 | 弹层 | **特殊笔记**（启动栏入口） | Trilium 的 Options/Note Map 都是笔记 |
| 知识图谱 | 弹层 | **右栏 · 笔记图** | 对标 NoteMap |
| 无限续写 | 弹层 | **对着一棵子树跑** | 原来是「文件夹级」，子树就是文件夹 |
| Skill | 弹层 | **树里的 Skills 分支**，一个 skill 一篇笔记 | 可编辑、可搜索、可克隆 |
| 设置 | 弹层 | **特殊笔记** | 同 Options |
| 用户切换 | 侧栏顶部 | **启动栏底部** | 对标 GlobalMenu |
| 命令面板 | ⌘K | **⌘J 跳转 + 命令面板** | Trilium 的 Jump to Note |
| 录音 | 工具栏按钮 | **启动栏 + 浮动按钮** | |
| 回顾 | 弹层 | **特殊笔记** | |
| 选区操作 / 出处 | 内联 | 原样保留 | 它们本来就是内联交互 |

## 2. 150 轮怎么分

| 轮次 | 阶段 | 做完的判据 |
|---|---|---|
| 1–15 | **树的后端** | `/api/tree` 一次拿全树；挂/摘/移动/克隆/展开都有端点和测试；`folders` 表和 `notes.folder_id` **删干净** |
| 16–40 | **主题与外壳** | Trilium 的 `theme-next` CSS 落地；启动栏/左栏/标签行/中栏/右栏/状态栏六块骨架立起来；亮暗两套都对 |
| 41–60 | **树控件** | 展开折叠、拖拽移动、克隆、右键菜单、快速搜索、当前笔记高亮、展开状态持久 |
| 61–75 | **标签页** | 多标签、分屏、前进后退、关闭恢复、⌘1..9 |
| 76–115 | **功能归位** | 上面那张表逐行落地，22 个组件各就各位 |
| 116–125 | **特殊笔记** | 设置 / 知识库 / Skill 变成笔记，可搜索可克隆 |
| 126–140 | **打包** | PyInstaller 打后端；electron-builder 出 .app/.dmg；图标、菜单、快捷键；**装到一台没有 python 的机器上能用** |
| 141–150 | **收尾** | 两端测试全绿；真机逐条走查；文档同步；旧代码删干净 |

## 3. 每一轮的固定动作

这套自查在上一个 100 轮里被反复证明有用，继续用：

1. 改完先跑两端测试（后端 pytest、前端 `npm test`）
2. 新加的断言**必须反向验证**——注入违规看它变不变红，不红就是空转
3. 界面改动截图看，不靠想象
4. 结构改动同步 `docs/`，`test_directory_map` 盯着图和代码一致

## 4. 明确不做

- 不移植 CKEditor（我们是 markdown + CodeMirror，产品既定选择）
- 不做同步 / 加密 / 移动端 / web clipper / 分享
- 不移植它的脚本系统（笔记里写 JS 执行）——那是另一个产品方向
