# MEMOKET NOTE · UI 规范

**这份文档是 UI 的唯一裁决依据。**以后往这个应用里加任何界面，先对一遍这里；
对不上就改界面，不是改文档（要改文档，先说清楚为什么，并改在这一份里）。

- **风格来源**：`memoket/memoket-desktop` 的 Design System v3
  （`electron/src/renderer/src/styles/design-theme.css`，本机检出在
  `~/code/memoket_desktop`），它自己又对齐移动端 APP 的 `AppTheme`
  （品牌紫 `#620FF0`）。
- **本应用现状**：配色和组件抄自 Trilium（`frontend/src/shell.css` 是 Trilium
  令牌，`frontend/src/styles.css:1-60` 是一层语义别名），accent 是蓝色 `#2563eb`。
- **这次要做的事**：把**视觉身份**换成 memoket 的，**布局和交互不动**。

## 0. 铁律

> **风格跟 memoket-desktop 对齐，布局和交互走这个应用自己的。**

抄的是颜色、字号字重、圆角、阴影、控件长相。**不抄**它的三栏结构、侧边栏导航、
录音条、MemoChat——那是另一个产品的 IA。这个应用的 IA 是 Trilium 式的
（启动器 + 树 + 标签 + 三栏 + ribbon），那部分已经做了 670 多轮，不动。

同理，**不抄它的 `[data-theme]` 切换方式**。这个应用的深色是
`@media (prefers-color-scheme: dark)`，桌面版靠 Electron `nativeTheme.themeSource`
驱动（`desktop/src/main.ts:304`）——网页版也能跟随系统，是有意的。
深色令牌一律写在 media 块里，**不要引入 `[data-theme]` 选择器**。

### 1.1b 面色必须是中性的

**紫是用来点的，不是用来铺的。**量过源仓库真 app 的像素：

| 面 | 它的值 | R−B |
|---|---|---|
| 侧栏 | `#F5F3F9` | −4 |
| 内容 | `#FCFBFF` | −3 |
| 卡片 / 页面 | `#FFFFFF` | 0 |

紫只出现在**小面积**上：品牌标记、选中态、主按钮、AI 卡片的底色。

第 690 轮的错：我把它**展示稿里那个假桌面色** `#E4E0F0`（R−B **−14**）
刷在了启动栏 + 标签条上——那是从上到下一整条大面积，于是整屏泛紫。
用户原话：「整个背景全用紫色？？？」

规矩：`--mk-bg / --mk-surface / --mk-paper / --mk-sidebar` 四个浅色面的色偏
（R/G/B 三者两两之差的最大值）**不许超过 6**；`check-ui-tokens` 会拦
（深色那几个面是源仓库自己合成的紫黑，APP 没有深色可抄，不在这条里）。

### 1.2 不动的令牌

- **`--jn-1..8`（屏幕活动的分类色）**：`shell.css:62-64`。这是一套过了
  色盲校验的 8 槽分类调色板，**换成品牌色系会毁掉它的可分辨性**。原样保留。
- **`--ins` / `--del`（修订的增删色）**：绿/红是 diff 的通用约定，跟品牌无关。
  保留，但深浅两套要跟新底色重新配一次对比度。
- **阴影不改配方，只换值**：源仓库的阴影是给窗口化应用做纵深的，这个应用同样是
  窗口化的，直接用它的四个。

### 1.4 `--ink-3` 不承载需要读的内容

这是上表第二行推出来的一条规矩，单独列出来因为它管的是**用法**：
`--ink-3` 只用于占位符、图标底色、分隔性的弱装饰。任何**用户需要读**的字
（标签、计数、说明、标题）至少用 `--ink-2`。

### 1.7 字体渲染与数字

| | 源仓库 | 这里（改之前） |
|---|---|---|
| `-webkit-font-smoothing: antialiased` | 有（`design-theme.css:104`） | **没有** |
| `text-rendering: optimizeLegibility` | 有（同上） | **没有** |
| `font-variant-numeric: tabular-nums` | 16 处 | 2 处 |
| `::selection` | 没有 | 没有 |

- 前两条不设，macOS 上同一个字号会比源仓库粗一号、糊一点。设在 `body` 上。
- **界面里的数字一律等宽字形**：计数、统计、时长在变化时不会左右跳。
  规则挂在 `.badge/.chip-count/.stat-value/.fact-meta/.pane-tab-badge/
  .ribbon-badge/.palette-when/.mini-bars-axis/.status-bar` 上。
- **`::selection` 两边原来都没有**——于是选中文字是浏览器默认的蓝，在一套紫色
  身份里很扎眼，深色下几乎看不清选了什么。这里补上 `--sel`。这条是**比源仓库
  多做的**，理由写在这儿。

## 2. 组件规范

每条都给了源仓库的 `file:line`。新加组件时按这张表挑，不要自己发明尺寸。

### 2.1 按钮

| | 值 | 源 |
|---|---|---|
| 高度 | `33px`（紧凑场合 28px） | `design-theme.css:222` |
| 圆角 | `var(--r-sm)`（9px） | 同 |
| 内边距 | `0 13px` | 同 |
| 字号/字重 | 13.5px / 600 | 同 |
| 默认态 | 透明底、透明边、`--ink-2` 字 | 同 |
| hover | 底 `--mk-hover`，字 `--ink` | `:223` |
| active | `transform: scale(.97)` | `:224` |
| 主按钮 | 底 **`--brand-fill`**（不是 `--brand`，见 §1.3 表）、白字、`--shadow-brand` | `:225` |
| 主按钮 hover | 底 `--brand-press` | `:226` |
| 危险按钮 | 底 `--live`、白字 | `:227` |
| 禁用 | `opacity:.5`，**并且必须有 title 说明为什么**（`check-a11y` 闸门） | 本应用 |
| 主按钮禁用 | **卸掉实心**：底 `--mk-bg`、字 `--ink-3`、`opacity:1` | 本应用，第 701 轮 |

**实心主按钮禁用时不能只是「淡一点」。** 走通用的 `opacity:.5`，白字压在半透明的
品牌紫上实测只有 **2.69:1**——而它常常是一个弹层里唯一的动作，标签本身就是在
告诉用户「这里要做什么」，看不清等于没写。淡下去的实心紫还有第二个毛病：
它看着像**能点、只是颜色浅**，而不是「关着」。

**默认按钮是「幽灵按钮」**（透明底 + 无边框），不是现在这种「有边框的白底方块」。
这是这次适配最显眼的一处变化：工具栏、面板里成排的按钮会安静下来，
主按钮因此真的跳出来。

### 2.2 输入

| | 值 | 源 |
|---|---|---|
| 高度 | 表单 `38px`，搜索条 `32px` | `shell.css:90` / `design-theme.css:171` |
| 圆角 | `var(--r-sm)` | 同 |
| 边 | `1px solid var(--mk-line)` | 同 |
| 底 | `var(--mk-surface)` | 同 |
| 聚焦 | `border-color: var(--brand); box-shadow: 0 0 0 3px var(--brand-weak)` | `shell.css:91` |
| placeholder | `--ink-3` | `design-theme.css:172` |

**聚焦环换成品牌紫的三像素光晕**，替掉现在那条 `:focus-visible` 的黑色 outline
（`styles.css:70`）。键盘可达性不变——只是换了长相。

### 2.2b 控件的尺寸变体归 CSS，不在调用处内联改

原生 `<select>` 的基类留了 `padding: 0 30px 0 10px`——右边那 30px 是给自绘箭头的。
右栏「记忆范围」那个下拉曾经在 JSX 里写 `padding: '1px 4px'` 把它改小，
**一下把整条 padding 冲掉**：文字压在箭头上、还顶出了自己的右边框（第 701 轮实拍）。

要小号就在 CSS 里给变体（`select.select-sm`：高 24、`--t-xs`、
`padding: 0 var(--s-7) 0 var(--s-4)`、箭头同比缩小），调用处只加类名。
**内联样式可以调位置（margin、flex），不许调尺寸和形态**（padding、height、
border-radius、font-size）——后者是控件的定义，属于 CSS。

### 2.11 手感与动效

源仓库有整整一层「手感」，这里原来几乎没有：**19 处过渡 vs 96 处**，
八个主要可交互面（树行、chip、链接、命令项、卡片、统计块、事实行、标签页）
**一个过渡都没有**——hover 是硬切。

| | 值 | 源 |
|---|---|---|
| 默认过渡时长 | `.12s`（源仓库 94 次用这一档） | `design-theme.css` 通篇 |
| 只过渡 | `background` / `color` / `border-color` / `box-shadow` | —— |
| 主按钮 | `transition: background .14s, box-shadow .16s, transform .08s` | `:355` |
| 主按钮 hover | `translateY(-1px)` + `--shadow-brand-hover` | `:358-359` |
| 主按钮 active | `translateY(0) scale(.985)` | `:361` |
| 普通按钮 active | `scale(.97)` | `:224` |
| 焦点环 | `2px solid var(--brand)`，`outline-offset: 2px`，跟随 `--r-sm` 圆角 | `:340-345` |

**不要过渡布局属性**（width/height/margin/padding）——会掉帧。只动颜色和阴影，
位移用 `transform`。

### 2.12 减少动态（可达性，不是可选项）

```css
@media (prefers-reduced-motion: reduce) { /* 动画与过渡一律近乎归零 */ }
```

这条原来整份 CSS **一个字都没有**。它不是效果开关，是**可达性**：前庭功能敏感
的人开了系统那个开关，界面就不该再动。源仓库有（`design-theme.css:369`）。

### 2.13 原生控件（勾选框 / 单选框 / 占位符）

**勾选框和单选框原来是原生的**（7 处）——macOS 上画出来是系统蓝，跟紫色身份
冲突，深浅两套下的边框也不跟主题。照源仓库的 `.task-check`
（`design-detail.css:117-119`）自己画：

| | 值 |
|---|---|
| 尺寸 / 圆角 | `17px`；勾选框 `--r-xs`，单选框 `--r-circle` |
| 边 | `1.6px solid var(--ink-3)`；hover 转 `--brand` |
| 选中 | 底和边都是 `--brand-fill`，勾 / 点是白色（`background-image` 画，不引资源） |
| 禁用 | `opacity: .5` |

占位符统一 `--ink-3`（源 `design-theme.css:172`）——原来吃浏览器默认灰，
深色下几乎看不见。

### 2.14 选中态的图标变品牌色

源仓库的签名动作（`design-theme.css:181`、`:190`）：选中行的**图标**转 `--brand`。
这里原来只有 chip 做了，树、笔记标签、ribbon 标签、右栏标签都没有——选中态只靠
一块底色表达，眼睛要找「我在哪」得先扫一遍背景。**图标是一行里最先被看到的那个点。**

### 2.15 滚动条

滑块平时透明，鼠标进到容器里才出现（源 `design-theme.css:313-315`，也跟 macOS
自己的习惯一致）。原来是一直显示，每一栏边上常驻一条灰杠。

这是一处「风格」而非「交互」的判断，所以可回退：去掉 `:hover` 前缀就回到常驻。

## 3. 新增界面必须遵守的硬规矩

1. **不写字面值**。颜色、字号、字重、圆角一律走令牌，只允许出现在
   `design-tokens.css` 里——**包括 tsx 里的内联样式**（`fontSize: 12` 不行，
   写 `fontSize: 'var(--t-sm)'`）。闸门 `check-ui-tokens` 四样都查。
2. **界面文字默认半粗**（`--w-semi`）。这是源仓库观感的主要来源，比字号更明显。
   阅读正文（编辑器里的字）保持 `--w-normal`。
3. **不发明尺寸**。按钮高度 33/28；输入高度 38/32；行高 36/34。

   > **把 `<button>` 重置成别的东西时，必须显式放开高度**（`height: auto`）。
   > 全局 `button { height: 33px }` 会漏进每一个这样的类：第 686 轮在
   > `.linklike`（长得像链接的按钮）、`.pane-tab`、`.ribbon-tab`、
   > `.palette-item`、`.topic-card-title` 上都实拍到了被撑成 33px。
4. **主按钮一屏一个**。品牌紫是「这一屏你最该点的那个」，摆两个就等于没有。

   > **例外：一屏是一串各自独立的决定时，每条一个主按钮。**
   > 实体合并收件箱是 68 张卡、每张问一个「是不是同一个」——**重复本身就是
   > 结构**，用户在同一个位置连点几十次，填充按钮是更大的靶子。
   > 判断标准：这些主按钮**互不竞争**（点哪一个不影响别的），而不是在
   > 同一件事上给两个出口。第 686 轮实拍合并页时对着这条规矩查出来的——
   > **一条人人都破的规矩，比没有规矩更糟**，所以写清例外而不是假装它没破。
5. **危险动作用 `--live`，并且要可撤销**（这个应用已有的 `toastAction` 模式）。
6. **深色一起写**。任何新令牌、任何新组件，浅色和深色同时给值；
   深色写在 `@media (prefers-color-scheme: dark)` 里，不用 `[data-theme]`。
7. **输入框要有名字**（`aria-label` 或可见 label）——`check-a11y` 闸门会拦。
8. **图标按钮要有 title**，**禁用按钮要说明为什么**——同一条闸门。
9. **能点的 div 要能键盘按**（用 `util/clickable`）——同一条闸门。
10. **分类色不碰 `--jn-*`**。那套是过了色盲校验的，改一个值就得重新验。
11. **可交互的东西要有过渡**（`.12s`，只动颜色和阴影），并且**只用
    `transform` 做位移**。加了动效就要确认 `prefers-reduced-motion` 那一块
    能关掉它。
12. **界面里的数字用 `tabular-nums`**。会变的数字不等宽就会左右跳。
13. **不用彩色 emoji 当图标。** 全应用的图标是 boxicons（单色、跟着
    `currentColor` 走）。emoji **拿不到令牌色**：深色下还是那几个彩块，
    也没法让「已完成」是 `--ins`、「写作中」是 `--brand`。
    第 687 轮清掉的：工具栏一排单色字形里那个 `🔗`、`✨ 智能排版`、
    `📥 存入知识库`、写作计划的 `⬜🔄✅` 三个状态。
    单色字形（`☑` `▦` `⚠`）可以留——它们跟着文字颜色走。
14. **不用原生 `input[type=checkbox|radio]` 的默认样子**。它们在 macOS 上是
    系统蓝，跟品牌冲突；已经在全局重画过一次，直接用就行。
15. **只给真的能点的东西加 hover 效果**。查过：`.card` 全是 `div`，给它们加
    hover 会让人以为能点。（我自己就先写了一条 `.card.clickable:hover`，
    一处都没用上——**写之前查，不是写完再查**。）
16. **`var(--x, 兜底值)` 里的兜底值只在真会用到时才写**。全仓扫过三处：
    `--card`（**根本没定义**，永远走兜底）、`--content-margin-inline`（有定义，
    兜底永远不触发）两处都删了；只有 `--tab-w`（运行时由 JS 写入）保留。
    **一个永远触发的兜底就是真值，只是藏起来了。**
17. **按钮的标签不能就是一个符号字形。** `<button>✕</button>`
    `<button>↺</button>` `<button>×</button>` 不是文字，是「用系统字体画的
    图标按钮」——粗细、字号、基线跟满屏的 boxicons 全对不上（第 701 轮实拍，
    8 处）。写法只有一种：
    `<button className="icon-btn" aria-label="…" title="…"><i className="bx bx-…" /></button>`。
    闸门 `check-icons` 第三条查这个，**判据故意收得很窄**——只认「整个子节点
    就是一个符号区字符」，汉字 / 字母 / 数字标签一概不碰（误伤比漏报贵）。
    注意这条跟第 13 条不冲突：单色字形当**内容**（`☑` `▦` `⚠`）照旧可以留，
    当**按钮的全部标签**就不行。

## 5. 怎么验

1. `cd frontend && npm test`（tsc + eslint + vitest + 23 条 check 脚本）；
   后端 `pytest` 不该受影响，但照跑。
2. **闸门 `check-ui-tokens`**：扫 `src/**/*.{css,ts,tsx}`，除 `design-tokens.css`
   外出现**字面颜色 / 字号 / 字重 / 圆角**就失败（CSS 和 tsx 内联样式都查），
   白名单里每一条要写明理由。**规范不上闸门就是许愿**（第 675 轮那条
   `check-a11y` 的教训）。
3. **实拍核对**：浅色 + 深色各一轮，至少覆盖首屏 / 知识库 / 笔记正文 /
   设置 / 导入 / 技能 六屏。用 `shot.sh <user> <probe> <name> [--dark]`。
   **改过字号或圆角之后还要再拍一次 1000×700**——字大一档最先撑坏的是窄窗。
4. **对比度要算，不要看**。第 679 轮实算抓到三处「看着没问题」的不过线
   （见 §1.3 表）。改任何颜色令牌之后重算这几对：白字/主按钮（亮+暗）、
   `--ink-2`/纸面、`--ink-2`/侧栏、`--ink-3`/纸面、`--ink`/纸面、`--brand`/纸面。
   正文级要 ≥4.5，纯装饰的 `--ink-3` 允许 ≥3。
5. **闸门自己也会出错，出错就修闸门**。这一段修过三处：`check-css-classes`
   把注释里的 `.cat-chip` 和 data URI 里的 `www.w3.org` 当成了选择器；
   `check-ui-tokens` 去注释之后行号偏移、报错位置是错的。
   **闸门不该被散文和 URL 绊倒。**

## 6. 这份规范明确不做的事

- **不动布局**。启动器 / 左树 / 标签栏 / 三栏 / ribbon / 状态栏的结构一律不动。
- **不动交互**。快捷键、右键菜单、拖拽、撤销全部不动。
- **不引入 `[data-theme]`**。见 §0。
- **不换图标库**。继续用 boxicons；源仓库用的是别的图标集，换一遍是纯粹的
  机械风险，且用户认得现在这套。
- **不抄 `--fs` 密度乘子**。源仓库每个字号都写成 `calc(13px*var(--fs))`，
  那是为它的「界面缩放」设置服务的；这个应用没有那个设置，抄过来是一层
  没人用得到的间接。要加密度设置，另开一轮，那时再引。
