## [684] 第 668 轮：真跑续写读产出 + 修掉我自己上几轮埋的一个性能坑（2026-09-15）

- **但顺着查下去发现我自己上几轮埋了个坑**：`kb/entities.for_store` 的缓存键里放了「人判过多少对」，于是**每次调用都要开一次 sqlite**——实测命中缓存时每次 0.454ms，其中 0.445ms（98%）是那次查询，等于把缓存的意义抵消了。而这个函数被 `search.rank` / `pages` / `notes` / `memory` 四条热路径反复调。

- 教训：**给缓存加键之前先想清楚「算这个键本身要多少钱」**。键算得比被缓存的东西还贵，缓存就成了摆设。
