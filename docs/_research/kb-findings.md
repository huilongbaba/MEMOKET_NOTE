# 知识库构建：现状实测（问题记录，待处理）

数据来自 2026-09-09 两个真实用户库。**先记录，架构梳理清楚之后再逐条处理。**

## 库存对比

| | terrence（原始） | terrence-rewrite（写作用） |
|---|---|---|
| 事实 | 20,406 | 2,896 |

## P1 主题碎片化（有数据）

| 主题事实数 | terrence | terrence-rewrite |
|---|---|---|
| ≤ 3 条 | 12% | **21%** |
| ≤ 5 条 | 17% | **33%** |
| ≤ 10 条 | 26% | **52%** |

**一半以上的主题材料不够写一段话。**

根因不是 bug，是 `kite_extract_profile._STRONGER_TOPICS_RULE` 主动要求的：
「不要满足于宽泛的根主题，提出更具体的子主题」。**主题更细对问答检索有利、
对写作有害**——这是「为写作重抽」这件事在主题粒度上做反了。

这条直接解释写作 harness 的 `non_repetition` 长期垫底：单主题材料不够，
写三轮只能重说。

## P2 覆盖不全

`terrence-rewrite` 只有 200/2429 units，时间停在 3/12。
`reextract.py` 是渐进式设计（跑一批停下来评估），跑到 200 就没继续。

## P3 主题体系不收敛

terrence 126 个主题里 **120 个是 `candidate` 态，只有 6 个 `canonical`**。
有状态字段，但没看到晋升机制在跑。

## P4 分块是固定字符数

`CHUNK_CHARS = 1200`，markdown 先按标题切、再按字符切；会议转写只按段落+字符切。
没有语义边界感知（一场会议中途换话题不会切开）。

**但要注意**：2026 年的多个 benchmark 显示**固定大小分块反而稳定胜过语义分块**
（Vectara NAACL 2025；FloTorch 2026 基准里语义分块产出平均 43 token 的碎片，
端到端准确率 54% vs 递归 512-token 的 69%）。所以这条**不一定是问题**，
要用端到端指标验证再动。

## P5 抽取质量没有判据

抽出来的事实好不好，**没有任何检查**——跟写作 harness 早期一模一样的处境。
可判的东西是有的：事实自不自足、有没有重复、主题选得对不对、有没有编造。

## 调研到的对照

- **GraphRAG**：实体抽取 → 实体消解 → **Leiden 社区检测分层聚类** →
  每个社区一份 LLM 摘要。它用「社区」解决的正是 P1 那个粒度问题——
  细粒度实体保留，但另外建一层聚合。
- **原子事实的粒度是公认难题**：「atomicity 的定义本身没有共识，
  标注者在粒度上分歧最大」；核心是 **atomicity-context trade-off**——
  越原子越丢上下文，越完整越难精确验证。
- **分块**：见 P4，固定大小是当前 benchmark 的胜者。
