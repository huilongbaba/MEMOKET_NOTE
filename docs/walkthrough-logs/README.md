# 走查日志：**留在这儿，为的是下一批能逐行 diff**

P83 的走查那一节末尾逐字写着：

> ⚠️ **这一批没能逐行 diff 到 P80 的原始日志**：P80 那份跑在它自己的 scratch 里，
> 这一批开工时**已经不在了**。…… 下一批要么把上一批的日志留在**固定位置**，
> 要么就别在任务书里写「逐行 diff 判」。

**这就是那个固定位置**（P85 C①）。一批一个目录（`p85/`、`p86/`…），
一步一个文件，文件名按走查表的顺序编号 + 身份 + 步骤脚本名。

## 存进来之前先洗一遍

原始日志里每批都会变的东西有一大把（note id、端口、pid、时间戳、今天是几号、
截图名的批次前缀、scratch 的绝对路径）。原样存进来，下一批 `diff` 出来是**满屏红**——
而一份永远全红的 diff 不是对账。所以存进来的是洗过的：

```sh
cd frontend
node scripts/walkthrough/normalize-log.mjs --today <这一趟跑的那天> \
  --out ../docs/walkthrough-logs/p86 <scratch 里那些 *.txt>
```

**洗掉了哪几类、哪几类一个字都没洗**，逐条写在 `normalize-log.mjs` 的抬头里。
一句话：**每批必变的洗掉，判据（字数 / 段数 / 项数 / 圆点 / 逐字文案 /
语料里的日期 / 亚像素坐标）一个字不动。**

「洗干净了没有」有闸看着：`node scripts/walkthrough/normalize-log.mjs --selftest`
（在 `npm test` 里）——例 / 反例 20 条，外加把**这个目录底下每一份**都扫一遍，
剩了 note id / 绝对路径 / 端口 / 时间戳**当场红**。

## 下一批怎么用

```sh
diff -u docs/walkthrough-logs/p85/06-old-b1old.txt docs/walkthrough-logs/p86/06-old-b1old.txt
```

差异**不等于**回退：换了一份 udd、换了种子标题、语料里多了一篇，都会让某些行变。
这份 diff 的用处是**把「要看一眼的那几行」缩到几十行**，判还是人判。

## 这儿存不了什么

* **截图**：不进 git（一批几十张 PNG）。它们在那一批自己的 scratch 里，台账记名字。
* **go.sh 那一层的输出**（起壳、端口对照、收摊）：那是量具自己的话，不是走查的读数。
* **真库**：一个字节都不进来。这些日志里凡是 note id 一律已经洗成 `<ID12>`。
* **第一批就能 diff**：不能。`p85` 是第一份，**跨批逐行 diff 从下一批起才做得了**——
  照实记，别把「留了地方」说成「已经对过账」。

## 第一次真做成是 P87（`diff p85 p87`）

**做成了，而且第一趟就抓到两笔**（细节在 `docs/TRACELOG-product.md` 的 P87 A 节）：

* **一条归一化的洞**：`/api/health` 回的 `{"pid":26273,…}` 里那个 pid **整整一批没洗掉**
  ——原来那条规则要求 `pid` 后面紧挨着 `=` / `:` / 空格，而 JSON 里中间隔着一个引号。
  它在 diff 上是**唯一一条纯噪声**。补规则 + 补「洗完不许剩下什么」那一侧 + 喂了
  正反例（含 `rapid` 这个不许洗的），并且**把 `p85` 那一份也重洗了一遍**
  ——新规则只管新日志的话，旧日志上那条噪声会永远躺在 diff 里。
* **一处台账跟日志对不上**：P85 的走查表把老用户 900px「横向溢出」记成 **0**，
  而 P85 **自己那份日志**（`p85/06-old-b1old.txt:96`）写着 **1**（溢出的是
  `note-tab active`「P58 走查（可删）×」）。**「台账上的数」和「日志里的数」是两把尺**
  ——这正是把日志留下来的全部意义：散文错了没人看得出来，逐行 diff 看得出来。

**做成之后的第二条经验**：`diff` 出来 78 行变动，**差异为 0 从来不是目标**。
能解释的差异分三类，每一类的处置不一样：

| 类 | 这一批占了多少 | 怎么处置 |
|---|---|---|
| **走查入参 / 素材不同**（截图前缀、种子标题、udd 是不是全新的） | 大头 | 照实记来源，**不追平** |
| **归一化没洗干净** | 2 行 | **补闸 + 喂反例 + 把旧的那一份也重洗** |
| **走查自己的随机性**（⌘K 候选序号、右栏刷没刷到） | 若干 | 记在案，看它下一批还在不在 |

解释不了的**当场记成问题**（这一批有一条：⑩ 那一格「润色」之后右栏没摆出「改动」页签，
而库里那一层两批**逐字节相同**）。

## P89 起：**这件事有闸了**（`frontend/scripts/check-walkthrough-diff.mts`，跑在 `npm test` 里）

上面那两段记的是「人跑 `diff`、人读」。P87 自己在末尾写着这件事没有闸，
而它同一批就用这份 diff 抓到了一处台账错——**能抓到东西的流程，只靠人记得跑是不够的**。

**归类表**：`docs/walkthrough-logs/<这一批>/DIFF-FROM-<上一批>.tsv`，每行五列（TAB 分）：

    类别 <TAB> 文件 <TAB> 方向 <TAB> 那一行逐字 <TAB> 为什么

* **方向** `<` = 只在上一批那一份里、`>` = 只在这一批里（跟 `diff` 的前缀逐字一样）；
  整份文件只在一边时是 `-` / `+`。
* **那一行逐字**就是 `diff` 打出来那一行去掉前缀之后的原文，**一个字都不许改**。
* **类别是闭集**（6 类）：`入参素材` / `归一化漏洞` / `走查随机` / `量具改了` / `产品改了` / `解释不了`。
  随手写一个词把事情盖过去，闸当场红。
* **「为什么」不许空**（至少 4 个字）。写「同上」是不够的——P89 自己被这一条拦过。

**闸判什么**：diff 出来的每一行，在表里有且只有一行（多集相等）。
diff 里有表里没有 → 红；表里有 diff 里没有 → 红（**上一批的归类照抄下来就是这样**）。
外加一条：**最新那一批必须有归类表**（不然「这一批忘了做」就是静默绿）。

**闸不判什么**：**「该有几行差异」一个数都没钉**——0 行绿、200 行也绿。
钉那个数等于每一次正当改动都红一次，而一条天天误报的闸迟早被人改成不红。
**归得对不对**它也一条都答不了：把 29 行全归成「入参素材」它照样绿。
它能做到的只有一件事——**让「都看过了」这句话变成 29 行写着理由的数据**。

比它老的那几批（`p85` / `p87`）**没有归类表，闸也不追认**：
那两趟不是我跑的，P87 的分类写在散文里、是 summary 级的，不是逐行的。
要补得有人真去逐行读那 78 行。

**P89 的第一次真用**：`diff p87 p89` = **29 行**（16 份里 12 份逐字节相同），
两类归完、**0 条解释不了**。其中 4 行「走查随机」查到底之后**顺手照出一处产品的洞**
（右栏「计划」页签在虚拟页上留着一片纯空白，而 `RightPane` 自己的注释写着「别留白」）。
⇒ **P87 用这份 diff 抓到一处台账错，P89 用它抓到一处产品留白。**

## 每一份日志头两行：**它是哪一份代码跑出来的**（P97 A + P99 A）

```
步骤脚本: panes93.mjs sha256=<64 位十六进制>
依赖: cdp.mjs=<64 位> provenance.mjs=<64 位> steps/lib52.mjs=<64 位> …
```

* **第一行**（P97 立）= 这一趟真读进来的那份**入口**步骤脚本的字节 sha256。
  为什么有它：P93 那一份日志**跑完 36 秒脚本被改过一次**，而入库的是改完那一份
  ——下下批的 diff 上就冒出一行查不清的噪声（P95 判「解释不了」，P97 查实了）。
* **第二行**（P99 补）= 这一趟**真读进来的其余那些字节**：被 import 的量具 + 驱动 `cdp.mjs` 自己。
  路径相对 `frontend/scripts/walkthrough/`，按名排序。
  这张单子是**顺着相对 import 走出来的闭包**，**不是整目录哈希**
  ——整目录哈希 = 隔壁那一步改一行这一批全红 = 一条天天误报的闸。

闸：`frontend/scripts/check-walkthrough-provenance.mts`（在 `npm test` 里）。
**两份豁免名单都逐字钉死**：`LEGACY`（连第一行都没有：p85…p95，**6 批**）、
`LEGACY_NO_DEPS`（只没有第二行：p97，**1 批**）。两份不许有交集。

⚠️ **代价**：**跑完走查再动 `cdp.mjs` / `lib*.mjs` / `provenance.mjs`，入库的日志当场红。**
顺序因此是「**先把量具定死 → 跑走查 → 跑完不动量具**」。
临时探针也得放进 `steps/`（闭包不许够到工具箱外头）。
