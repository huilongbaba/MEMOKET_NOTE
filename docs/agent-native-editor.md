# Agent-native 编辑器：它应该长什么样

> 这份是**方案**，不是改动清单。`product-north-star.md` 定了三条判据；这份回答
> 「按这三条判，现在的编辑器为什么还像个传统编辑器，agent-native 到底要长出什么」。
> 写的时候我把自己当成一个每天写会议记录、周报、复盘、研究笔记的重度用户来想。

## 0. 一句话

传统编辑器：**文档是产物，AI 是你偶尔叫来的工具。**
Agent-native 编辑器：**文档是你和一个 agent 共用的工作台——它知道这篇要干什么、
记得你写过什么、会自己往前推进，但每一步都落在页面上、可撤回、不需要你跟它说话。**

判据不变（北极星的三条）：一个按钮完成一件事；不离开页面就用得上记忆；说「我要什么」
而不是「你下一步做什么」。下面每一条设计都标了它兑现哪条判据、解哪几个痛点。

## 1. 诚实地看现在：为什么还像传统编辑器

现在的 MEMOKET NOTE 已经把三条判据各做了一半，但骨子里还是「编辑器 + 挂件」：

| 现在的样子 | 为什么不够 agent-native |
|---|---|
| AI 能力都是按钮（续写 / 润色 / 校验 / 插图 / 表格 / 数据分析…） | 它们是**作用在一段文字上的动词**，彼此不认识：润色不知道这篇的目标，插图不知道上一张图是拿什么数据画的，校验不知道你上周已经核过这一段。按钮之间没有共享的「意图」 |
| 右栏有「记忆」面板跟着正文浮现相关事实 | 它是**被动的旁观者**：躺在右边等你看。真正的记忆应该在你写到「DVT 延期」的那一行旁边告诉你「上次说的是 6 月 3 日，后来改到 8 月 5 日」，而不是要你转头 |
| 有骨架（spine / beats）、有智能续写 harness、有分段写作计划 | 骨架是「点一下生成」的元数据，harness 是「点一下开始跑」的模式。**默认状态下文档不知道自己要干什么**，agent 只在你按下按钮的那几十秒里存在 |
| 改动有 track-changes、逐处接受 / 撤回 | 只有「这一轮」的改动。痛点 8 要的是「保留第一次改的、放弃第三次改的」——那是**改动的分层历史**，不是一层高亮 |
| 知识库是树上的虚拟子树、有反向链接 | 知识库和笔记之间是「引用」关系，不是「材料」关系：写周报时我要的是**把这八篇笔记摊在桌上**，而不是逐条搜事实 |
| 导入 Obsidian / Evernote / Notion，导出 zip | 单向、一次性。痛点 10 的本质是「材料在别处」，需要的是**持续同步的材料源**，不是搬家 |

一句话：现在是「好用的编辑器 + 一排好用的 AI 按钮 + 一个知识库」。agent-native 要的是
这三样长成一个东西——**页面本身就是 agent 的身体**。

## 2. 深度用户的一天（先看体验，再看结构）

### 场景 A：周五下午写周报（痛点 3、13、1.5、1.7）

我新建一篇，标题「第 37 周周报」。编辑器**没有**弹一个聊天框问我想写什么。标题下面出现
一行浅灰的「这篇要干什么」——它已经填好了草稿：`目标：本周工作汇报 · 读者：老板 ·
材料：本周 5 篇会议记录、2 篇随手记 · 完成标准：每条进展有日期有依据`。这是从标题、
从日历、从最近一周的笔记推出来的；我改两个字或者不改。

正文左侧的**材料托盘**已经摊开了那 7 篇笔记（缩略：标题、日期、三行摘要）。我拖两篇
不相关的出去。点「按材料起草」——不是聊天，是一个按钮——agent 按「这篇要干什么」写
出骨架 + 每节一段初稿，**每一段的右边缘挂着它用了哪几条材料**（小圆点，悬停看原文）。
时间线不对的地方（上周说 6/3、这周说 8/5）它自己标了黄：「两处日期冲突，取后者？」——
我点一下「取后者」。

我改了三段、删了一段。再点「核对」，它只核我改过的和它拿不准的，绿钩 / 黄标就地出现。
最后点「排版」，结构不动，只把列表、表格、空行收拾整齐。整个过程我没有离开这一页，
没有粘贴过一次，没有跟谁「说」过话。

### 场景 B：写复盘写到一半想查旧账（痛点 11、12）

写到「众筹定价 199」时，我不确定当初是怎么定的。我不去搜索——把光标放在「199」上，
按 ⌥（或者悬停半秒），旁边弹出**来龙去脉卡**：三条按时间排的记录，「2 月 24 日说
砍配件、3 月 10 日定 199 可退、4 月 10 日改预售」，每条能展开原话。我点「引用这条」，
它变成行内出处，我接着写。

如果我真的点进了旧笔记（有时候确实要读全文），编辑器顶上留着一条**「你正在写：
第 37 周周报 › 定价一节，你来是为了查 199 怎么定的」**。看完点「回去」，光标回到
「199」后面，卡片上还贴着我刚读的那段的摘要，问我要不要插进去。思路不断。

### 场景 C：AI 改了三轮，我只想要第一轮（痛点 8）

「润色」这个按钮我按了三次，每次不满意就再按。第三次之后我发现第一次其实最好。
右栏「改动」标签里是**三层**：`润色 ①`、`润色 ②`、`润色 ③`，每层能单独开关、能只
接受其中几处。我关掉 ②③，留 ①，正文立刻回到第一版的样子。没有「你把第三次的
去掉」这种话要说。

### 场景 D：一段录音、一张截图、一个网页（痛点 1.2、1.3、1.9）

我把手机录的 40 分钟录音拖进托盘。它不进正文——它变成一份材料：转写、抽事实、
入知识库，托盘里显示「已转好，12 条事实」。我在正文里写到相关的地方，右缘的小圆点
亮了：这段有材料可用。截图拖进来也一样：识别成表格材料。网页链接贴进托盘：抓正文、
摘要成材料。**材料和正文是两层**，正文只放我要的，材料层由 agent 维护。

### 场景 E：做成 PPT（痛点 1.6）

不是「导出成 PPT 然后去另一个工具改」。点「视图 › PPT」，右侧出现这篇笔记的**幻灯
视图**——每个二级标题一页，图表原样带过去，讲稿是每节的第一段。我在幻灯视图里改
了一句话，正文里对应那句也变了（同一份数据的两种视图）。导出只是把当前视图落成文件。

## 3. 八个构件

每个构件写：它是什么 → 兑现哪条判据 / 解哪些痛点 → 现在有什么 → 要长出什么。

### 3.1 文档意图（Doc Intent）：每篇笔记知道自己要干什么

**是什么**：笔记的元数据区常驻一块「这篇要干什么」：目标、读者、材料范围、完成标准、
截止。agent 的每一个动作（续写 / 润色 / 校验 / 起草）都以它为前提；它变了，agent 的
行为跟着变。它可以由 agent 从标题和上下文**预填**，用户改一个字就是「校准」。

**判据 3**（说「我要什么」）；痛点 1.5（润色丢结构：因为不知道结构是为谁服务的）、1.7、3。

**现在有**：spine / beats（骨架）、写作计划的 goal。它们是「生成出来」的、只在 harness
里用。

**要长出**：把 spine/beats/goal 合并成 Doc Intent，放在标题下面（不是 ribbon 的一个
标签），新建笔记时自动预填（从标题、日期、最近材料），所有 prompt 的第一段都是它。
「完成标准」是可检查的（每条进展有日期、有依据、≤ 800 字…），校验按它核。

### 3.2 在页面上的 agent：所有动作都是「提案」，提案有分层账本

**是什么**：agent 不说话，只改页面。每次改动是一个**提案层**（proposal layer）：
有名字（润色 ②）、有来源（哪个按钮、什么时候、依据什么材料）、有范围（哪几处）。
层可以整层开关、逐处接受、按层撤回；层之间的冲突（②和③改了同一句）按后者优先但
两者都保留。接受 = 把这层「烧」进正文；关掉 = 正文回到没有这层的样子。

**判据 1**（一个按钮一个可预期的结果）；痛点 8（AI 失控）、1.1、1.7。

**现在有**：`roundDiff` 一层 hunk + 接受/撤回；历史版本（十分钟一版）。

**要长出**：hunk 带 `layer` 字段；右栏「改动」标签列出层；层的开关 = 重放 / 撤销
该层的 hunk（顺序无关的部分直接切换，有冲突的按层序重算）；「接受全部」变成「烧掉所有
打开的层」。历史版本保留每次「烧」之前的快照。

### 3.3 边缘记忆（Margin Memory）：记忆贴在正文旁边，不在右栏等你

**是什么**：正文每一段的右缘是一条「记忆带」：跟这段相关的事实、旧笔记、时间线以
小圆点出现，悬停展开，点一下引用。对时间、数字、人名这类**可核对的东西**，agent
主动比对知识库：一致就静默，不一致才亮黄点（「上次记的是 6/3」）。⌥ 悬停任何词
就是「来龙去脉」（现在右键菜单里的那个），结果贴在词边上。

**判据 2**（不离开页面）；痛点 11、12、13。

**现在有**：右栏「记忆」面板（被动）、行内出处 peek、右键「来龙去脉」（结果落右栏）。

**要长出**：段落级 recall（按段落文本查，不是按尾部 500 字）；CM 的 gutter/widget
画圆点；数字 / 日期 / 实体的**冲突检测**（知识库里同一 obj 的事实 vs 正文里写的）；
「来龙去脉」改成锚在词上的卡片。

#### 3.3.1 记忆不只是「相关」：六种关系

「相关记忆」这个词太弱了——它只回答「知识库里有没有类似的」。一个真正记得事的
同事，看到你写的一句话，会告诉你它跟过去的记录是**什么关系**。按对写作者的用处分：

| 关系 | 你写的 | 知识库里 | agent 应该说 | 颜色 |
|---|---|---|---|---|
| **冲突** | DVT 6 月 3 日 | 4/10 定 6/3，5/8 改到 8/5 | 「跟 5/8 的记录冲突：已改到 8/5。用新的？」 | 黄 |
| **延续** | 电池改 380mAh | 3/10 说 150→200，4/10 说 200→300 | 「这是第三次改：150 → 200 → 300 → 380」——给一条演进线 | 蓝 |
| **叠加** | 众筹订金 199 | 199、可退、7/1 前、只限首批 | 「知识库里关于这个还有 3 个条件你没写」——补齐同一件事的属性 | 蓝 |
| **合并** | 「王工负责测试报告」 | 「王工补通信测试报告」「测试报告下周三给」 | 「这两条说的是同一件事，合成一条？」——去重是写作者的活，不是抽取器的 | 灰 |
| **印证** | 通信切到 2.4G | 有 2 条一致记录 | 静默，出处圆点变实心；悬停看是谁、哪天说的 | 绿（默认不亮） |
| **缺依据** | 「用户反馈续航不够一天」 | 找不到任何记录 | 「没有记录支持这句」——不是说它错，是说它没根 | 灰点 |

再往深一层，这些关系不只在写作时用，它们是**知识库自己的结构**：

- **事实有生命周期**：一条事实可以被另一条**取代**（supersedes）。「DVT 6/3」被
  「DVT 8/5」取代后，实体页 / 主题页默认只显示**当前状态**，历史折叠在「演进」里。
  现在的知识库把 20406 条平铺，用户看到的是三条互相矛盾的日期，不知道哪条算数。
- **同一件事有一条线**：按 obj（KITE 抽取时已经给了 `obj` facet）把事实串成演进线，
  实体页多一节「这些事怎么变的」——痛点 13「捋不清时间线」的根子在这里。
- **冲突有收件箱**：摄入时就检测新事实跟旧事实的冲突（同 obj、同类属性、值不同），
  放进「待处理」而不是静默入库；用户点一下「新的取代旧的」或「两条都留」。
- **合并是用户确认的**：抽取器去重永远做不干净（实测 memo cat / MemoCat 这类），
  agent 提议、用户确认，合并结果记住（下次不再问）。

怎么检测（不靠一次大 LLM 调用）：

1. **候选**：正文的一段 → 抽出数字 / 日期 / 实体 / obj（现有的 recall 词法层 +
   一次轻量抽取），拿 obj + 实体去知识库取同一件事的所有事实（KITE 的 `obj`、
   `entities`、`t` 都在）。
2. **判关系**：同 obj 同属性值不同 = 冲突候选；同 obj 值按时间递进 = 延续；同 obj
   属性并集比正文多 = 叠加；两条事实文本高相似 = 合并候选。这一步是代码，毫秒级。
3. **只对候选打一次 LLM**：把候选和正文那句一起给模型，让它确认关系并写一句人话。
   没有候选就不打——大多数段落是静默的。
4. **落在页边**：圆点颜色 = 关系类型；悬停是卡片；卡片上的动作是按钮（用新的 /
   补进来 / 合成一条 / 引用这条 / 忽略），不是对话。忽略要记住。

这一层的价值在于：写作者不用记得知识库里有什么，**知识库会在该说话的时候说话，
而且说的是关系，不是「相关」**。

### 3.4 材料托盘（Material Tray）：正文之外的第二层

**是什么**：每篇笔记有一个材料区（左栏或正文顶部可折叠）：拖进来的旧笔记、录音、
图片、网页、文件、知识库里搜出来的一组事实。材料不进正文；agent 负责把材料**变成
可用的形态**（转写、抽事实、识别表格、摘要），并在你写到相关处时提示。「按材料起草」
「按材料核对」「按材料补图」都以托盘为范围。

**判据 2 + 3**；痛点 1.2、1.3、1.9、1.10、3、13。

**现在有**：摄入（存入知识库）、导入（Obsidian / Evernote / Notion / .md）、录音转写、
图片转表格——都是「进正文」或「进知识库」两个去处，没有「材料」这一层。

**要长出**：`note_materials` 表（笔记 ↔ 材料，材料 = 笔记 / 摄入单元 / 文件 / 网页）；
托盘 UI；起草 / 核对 / 补图三个按钮改成「以托盘为材料范围」；导入的东西默认先进托盘。
「笔记 ↔ 知识库链接层」（这篇贡献了哪些事实、改了要同步）是它的地基——先做。

### 3.5 默认在跑的 harness：规划是页面的一部分，不是一个模式

**是什么**：Doc Intent 一旦有了，编辑器就有一个**常驻的计划**（大纲 + 每节状态：
空 / 草稿 / 已核对 / 已定稿）。agent 按计划推进：你写的节它核对、空的节它起草、
材料变了它标「需要更新」。它不会自己「烧」进正文——一切经过提案层。你随时改计划
（拖动节、改标题、删节），agent 跟着计划走。

**判据 3**；痛点 3、13、1.7。

**现在有**：写作计划面板（子树级）、智能续写（单篇）、目录。计划和目录是两个东西。

**要长出**：目录 = 计划（每个标题带状态和「用了什么材料」）；「自动推进」开关（默认
关，开了之后 agent 在空闲时起草空节、核对改过的节，都以提案层出现）；每一轮的判据
（现在的 rubric 维度）显示在节旁边而不是面板里。

### 3.6 万物皆块、块带出处：图、表、段落都记得自己是怎么来的

**是什么**：每个 agent 生成的块（图表、插图、表格、一段文字）带一张「出处卡」：
用了哪些材料、哪个按钮、什么时候、参数是什么。于是能「用最新数据重画」「按新材料
重写这一节」「这张图为什么在这」。

**判据 1 + 3**；痛点 1.3、1.4、1.5。

**现在有**：`TapProvenance`（续写的材料来源，折叠）、块生成走 harness（有 trace）。

**要长出**：块级出处存进正文旁的 sidecar（不污染 markdown：`<!-- prov:… -->` 或按块
id 存表）；出处卡 UI；「重做」按钮（同参数 + 新材料）。

### 3.7 视图（Views）：PPT / 网页 / 邮件是同一篇笔记的另一种看法

**是什么**：笔记是唯一的真相，PPT、网页、邮件、一页纸摘要是**视图**——由 agent
按规则（每个 H2 一页、图原样、首段作讲稿）生成，在视图里改字会写回正文（结构性
改动只在正文做）。导出 = 把当前视图落文件。

**判据 1**；痛点 1.6、1.8（改完再给我一个网页——因为网页不是视图，是另一份副本）。

**现在有**：导出 Markdown zip；`/用 AI 写`。

**要长出**：视图渲染层（先 PPT 大纲 + 网页两种）、视图内联编辑回写、导出 pptx / html。

### 3.8 注意力守卫（Attention Guard）：离开是为了什么，回来接得上

**是什么**：从正在写的笔记跳走时（点了树、点了搜索、点了链接），编辑器记下「从
哪一段离开、为了什么」（为了什么 = 光标所在句 + 最近一次搜索词）。回来时光标回到
原处，顶上一条「你刚去看了 X，要不要把它引进来」。能不跳走的尽量不跳：树上 ⌥ 点击
是快速查看、链接悬停是预览、来龙去脉贴在词边。

**判据 2**；痛点 11、12。

**现在有**：前进后退、快速查看、链接悬停卡、来龙去脉。

**要长出**：离开上下文的记录（栈）+ 回来时的提示条 + 「引进来」动作；跳走时右栏
记忆面板锁定在离开前的段落而不是跟着新页面变。

## 4. 这些构件之间怎么咬合

```
Doc Intent ──────────────── 所有 prompt 的第一段
    │
    ├─ 计划（3.5）= 目录 + 每节状态 ──── agent 推进的依据
    │
材料托盘（3.4）──→ 边缘记忆（3.3）──→ 提案层（3.2）──→ 正文
    ▲                    │                  │
    │                    │                  └─ 块出处（3.6）──→ 视图（3.7）
知识库 ◄── 笔记贡献的事实 / 同步（链接层）
    │
注意力守卫（3.8）贯穿：任何离开都带着「为了什么」回来
```

关键的一条边是**笔记 ↔ 知识库的链接层**（这篇贡献了什么、改了要不要同步、知识库
里的东西能回到哪篇）：托盘、边缘记忆、块出处都建在它上面。所以它排第一。

## 6. 分期

按「先解最疼的、先铺地基」排：

**M1（地基 + 最疼的三个痛点）**
1. 笔记 ↔ 知识库链接层（贡献列表 / 增删改 / 过期标识 / 同步 / 自动同步开关 / 反链）
2. 提案层：hunk 带 layer，右栏「改动」标签，层开关（痛点 8）
3. 边缘记忆第一版：段落级 recall + gutter 圆点 + 六种关系里先做**冲突 / 延续 / 缺依据**
   三种（代码判候选 + 一次 LLM 确认）；知识库侧先做「事实取代」和实体页的演进线

**M2（材料层）**
4. 材料托盘 + 导入默认进托盘 + 「按材料起草 / 核对」
5. Doc Intent 合并 + 预填 + 进所有 prompt
6. 注意力守卫（离开栈 + 回来提示）

**M3（自动化成为默认）**
7. 目录 = 计划 + 每节状态 + 自动推进开关
8. 块出处 + 重做

**M4（视图）**
9. PPT / 网页视图 + 回写 + 导出

导入 / 同步 / 导回（飞书、Obsidian、Notion 的双向）是 M2 材料层的输入端，单独一份
`import-sync-plan.md` 写（增量、断点续传、进度 / 用量 / 预估时间也在那里）。

## 7. 明确不做的

- **不做聊天框。** 任何时候想加聊天框，先问：这个意图能不能封装成按钮 + Doc Intent。
- **不让 agent 直接改正文。** 一切经过提案层。自动推进也只产生提案。
- **不做「AI 猜你想写什么」的空白页生成。** Doc Intent 预填是可见、可改的，不是替
  用户决定。
- **不把材料塞进正文。** 材料层和正文层分开，正文只放用户要的。
