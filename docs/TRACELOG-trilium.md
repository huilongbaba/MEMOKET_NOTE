## [715] 第 699 轮：`.linklike` 的契约被我破了（2026-09-15）

上一轮修了 toast，但那只是症状。回头看根因：

`.linklike` 本来是 **`color: inherit`**——它的整个用处就是「长得跟旁边的文字一样，
但能点」。状态栏的红色告警（`.health-bad`）、屏幕活动的危险动作（`.danger`）、
toast 的反底，全靠它继承上下文的颜色。

- toast 里的「撤销」成了深紫压近黑（第 698 轮修的症状）；
- 状态栏「语音离线」的红告警被染成紫——`.health-bad` 定义在 `.linklike` 前面，
  **同权重后来者赢**；
- `.danger` 那条侥幸没坏（`button.danger` 是 0,1,1，压得过 0,1,0）。

**逐个打补丁是错的方向**：基类恢复 `color: inherit`，要「看得出可点」就加
`.link`（本来就有这个修饰类）——实体合并卡那两个改成 `linklike link`。
toast 那条反底规则保留（它是真的需要特例）。

实拍 + 量像素核对：toast「撤销」`#FFFFFF`，合并卡那两个是链接色。

**教训**：改一个基类之前，先问它现在这个值是不是**故意**的。
`color: inherit` 看着像「没写」，其实是契约。

## [746] 第 738 轮：菜单 95% 在屏幕外——`backdrop-filter` 抢走了 fixed 的包含块（2026-09-16）

x=1175 起、宽 311，y=763 起、高 447 —— **95% 在屏幕外面**。

根因是一条 CSS 的硬规矩：**`backdrop-filter` / `filter` / `transform` /

一个浮层不该依赖它被挂在哪——这是组件自己的责任，不是每个调用处去躲开
带滤镜的祖先。（React 的事件冒泡仍走组件树；`ref.current.contains()`
也照常，ref 指的是真实 DOM 节点。）

顺带去掉两个魔数锚点：`y: r.bottom + 4`（往下弹，而下面就是窗口边缘）和

## [750] 第 748 轮：屏幕活动为什么只有计时没有描述——两个进程抢同一个文件（2026-09-17）

第 746 轮我在壳里加了自动补描（开后 30 秒一批、之后每 3 分钟一小批），当时
留了一句「**我还没亲眼看到描述生成出来**」。这轮把它验完了，结果不是「没跑」，

### 证据链

装好的 `app.asar` 里 `describeBacklog` 在（4 处「自动描述」字样），日志里
`POST /api/journey/catch-up?limit=4 200 OK` 刷了几十条，其中 3 条

这正是「**验到调用成功 ≠ 验到结果对**」那条：200 只说明请求到了后端。

### 根因：`segments.json` 有两个写的人，各写全份

- 壳（`capture.ts` 的 `flush`）每切一段就把**内存里那份**整个写下去；
- 后端（`journey.py` 的 `_save`）描述完把**它手里那份**整个写下去。

描述一段要 15–20 秒。这期间壳至少落一次盘，把没有 `desc` 的那份盖回去。
下一轮后端再挑同一批重描——**永远循环**。

**比丢描述更糟的是丢图。** 后端描述完会删大图（`_drop_frame`，这是隐私承诺的
一部分），壳紧接着把 `frames: ["…/001.png"]` 这个路径写回来，**而文件已经没了**。
那一段从此永久是「没有截图」，再也补不回来。实测今天 71 段里
**活着的大图 0 张**，而磁盘上还躺着 63 张——文件名正好交错（001 没了、002 还在、
003 没了…），因为留下的那些是 `mergeBlips` 合并掉的短段，**没有任何代码会去清它们**
（后端的过期清理只遍历段表，扫不到无主文件）。这条对着产品自己写的
「描述做完就删大图」是反的。

### 改法：各写各的字段

| 归谁 | 字段 |
|---|---|
| 壳 | `start` `end` `app` `title` `n` |
| 后端 | `desc` `skip` `session` `deleted` `frames` |

- `capture.ts` 新增 `keepBackendFields(fresh, disk)`：落盘前按 `start` 对齐，
  把盘上那份里后端写的字段贴回来。墓碑（`deleted`）整条用盘上的——删段会把
  app / title / n 一起清掉。
- `journey.py` 新增 `_merge_back(disk, ours)`，`_save` 改成先重读再贴：
  我们手里那份是 20 秒前的旧快照，**段表本身归壳**（它还在往后长），
  盘上有、我们手里没有的段原样留着。
- `capture.ts` 新增 `sweepOrphans(dir, segs)`：落盘后删掉没人引用的
  `shots/*.png` / `thumbs/*.jpg`。只删**两分钟前就躺在那儿**的——刚拍下来那张
  正要进段表，别自己删自己。缩略图只要还被段引用就留着（一句没有凭据的
  描述，用户没法判断真假）。

### 闸（`check-journey-merge.mts`，本来就是管「壳和后端两份实现别漂」的）

四条新判据，每条都**反向验过**（把修复撤掉必须变红）：

| 判据 | 突变 | 结果 |

## [754] 第 752 轮：日报喂进去的还是原始段，同一件事喂八遍（2026-09-17）

[752] 在时间轴上把「连着说同一件事」的段并成了块，但**日报那一路没跟上**：
`report()` 里 `lines` 仍是一段一行。同一件事以八条近似重复的样子进提示词，
模型看到的是「这件事出现了八次」——这一天真正推进了什么反而被那八遍压下去。

后端加 `app/journey/runs.py`（纯函数，跟 `journey/` 这个包的规矩一致：
**能用规则算准的就不交给模型**），`report()` 改成按块喂，并带上「N 段」，
让模型仍然知道这件事占了多少时间。

实测（同一批真实描述）：8 行 → **6 行**；而旧包那批 20 条应用一直在换，
**20 → 20 一条没并**——判据窄，该不并就不并，这正是想要的。

### 两份实现，钉在一起

前端 `util/journeyRuns.ts` 和后端 `journey/runs.py` 是同一套判据。
漂了的后果很具体：**页面上并成一块的事，日报里却按八件事算权重**。
所以进了 `check-journey-merge.mts`（它本来就是管「两份分段实现别漂」的）：
8 个分块用例逐位对拍 + 相似度分数对拍 + 两个门槛对拍。

`similar` 两边都写成二元组 Dice 而不是用 `difflib`——**后者没法在 TS 里原样复刻**，
而这条判据的全部意义就是两边给同一个数。

**突变验的时候抓到自己判据不够**：把后端 `SIM` 从 .45 调到 .30 当场变红，
但把「跟块首比」改成「跟上一条比」**一条都没红**——对拍用例里缺那条会飘的链
（a 像 b、b 像 c，而 a 跟 c 已经是两件事）。补进去之后突变立刻被抓住。
*闸跑绿不等于闸有用，这一条又验证了一次。*

## [755] 第 753 轮：日报说你「连续专注了 10 小时 45 分钟」——人在睡觉（2026-09-17）

真写了一份日报出来读（**读产出**，这一段最有效的方法）。模型写的那三节没问题，
**代码算出来的那一半露了馅**：

```
连续没被打断的几块：
- 00:00–10:44 MEMOKET NOTE 10 小时 45 分钟
```

人在睡觉。屏幕亮着、前台窗口没变，于是 `changed` 一直是 false，
那一段 `end` 一路延到早上。

**这条对这个功能是致命的**：整页的前提是可信（§8.3「难点不是时间轴是信任」），
而这句话是假的。锁屏 / 睡眠已经会自动暂停了，但这次两样都没发生——
显示器没关、机器没睡。

### 正确的信号本来就有

`powerMonitor.getSystemIdleTime()`（秒）。当场量过：这台机器上返回 0、
`getSystemIdleState(300)` 返回 `active`，跟 `ioreg -c IOHIDSystem` 的
`HIDIdleTime` 对得上。**离开 5 分钟就不记**——五分钟是这类判断的通行值，
也够宽：读一屏长文、开会听着不动手都到不了。

跟锁屏 / 睡眠自动暂停是同一条理由：「离开座位时还在录」最让人不安。

### 两处讲究

- **`capture.ts` 不 import electron**：它要能在对拍脚本里当普通模块 import。
  所以 `makeRecorder` 多收一个 `idleSec: () => number`，壳那边注入
  `powerMonitor.getSystemIdleTime`。
- **段尾收回到 `now - idleSec`**，不是停在上一 tick：`getSystemIdleTime` 给的是
  精确的「多久没动过」，比 15 秒一跳的采样准，也不用另存一个时间戳。
  只往回收不往前推（时钟跳变不能把一段拉长），收过头就停在 `start`
  （宁可留一个零长段，也不要 `end` 早于 `start` 的坏数据）。

### 验

四条判据进 `check-journey-merge.mts`（对拍判据 24 → 28）。
**端到端也验了**：把门槛临时压到 5 秒、用 dev 实例真跑一遍，日志里出现
`[journey] 人离开了（0 分钟没动），先不记`——从 `powerMonitor` 到 `tick`
到 `trimIdleTail` 到落盘整条链路是通的。（正式门槛下会写「5 分钟没动」。）

### 已经记下的那一天补不回来
没有 idle 的历史，那条 10 小时 45 分钟的「连续块」改不了。从这一版起才准。

## [756] 第 767 轮：跑的过程中那条状态横条挡着正文（2026-09-18）

用户实拍：「Agent运行的状态能不能去掉，或者放在 续写、停止那一行，即续写的左边，
你这样搞挡着编辑板了」。截图里正文第一行「## 这份需求文档用了统一 EVT 阶段的
交付边界与评审依据」被那条横条压掉了大半。

### 为什么它会挡

`.harness-sticky` 是 `position: sticky; top: var(--fb-band-height)`——**它是占行的**，
不是浮层。于是整轮几十秒里，正文顶部被硬生生推掉一行。而同一句话
（「第 9 轮：修订 3 处，续写中…」）另外**两个地方也在显示**：右栏「Agent 运行」
和底部状态栏。**这里是第三份。**

### 改法

- 跑的过程搬进 `.floating-buttons` 那一排，做成 `.fb-status` 胶囊，
  放在「续写」左边（用户指定的位置）。那一排是 `height: 0` 的浮层，**不占正文的行**。
- 那句「运行中正文由 AI 接管，停下来再改」收进 `title`——它是解释，不是每秒都要读的。
- **横条只留下两种，都是「等你动手」**：轮末暂停（带「接着写 / 到此为止」两个按钮）
  和跑完（一句话 + 关闭）。那两种本来就该停在眼前，不是这次要治的东西。
- `max-width: min(360px, 38cqw)` + 省略号：状态文案是模型给的，长度不可控，
  **不压住就是换个地方接着挡**。窄容器（≤380px）下整个收起来，不然把按钮挤出可视区。

### 两条教训

1. **闸先抓了我一次**：第一版 `border: 1px solid var(--border)`——`--border` 这个令牌
   **根本不存在**，`var()` 会静默退回继承值。仓里那条「颜色/字号/圆角都走令牌」的闸当场红。
   （`shell.css` 第 735 轮的注释里记着同一个形状：`--right-pane-header-height` 写在注释里
   但没定义，值是写死的 34。）
2. **当时没有任何探针能摆出「跑到一半」这个状态**——`tap:` 那个是真跑，要花钱、还会
   写进笔记库。差一点就靠「`.floating-buttons` 是 `height: 0`，结构上挡不着」交差，
   而这个仓反复证明过**推理不算数**。补了 `running:<noteId>` 探针：状态就两个 useState，
   摆出来**不需要任何网络**。实拍确认横条没了、胶囊在「续写」左边。
