**范围**：用户指令「抄 TriliumNext/Trilium 的前端，适配我的功能，做成
Electron」「全部按照 Trilium 做」「做一个 150 轮的计划，全部改造完，并且我做
的功能要适配这种风格和交互格式」。计划见 `docs/trilium-migration-plan.md`。

**这份文档的用处**：每一次改动 + 它的测试情况记一笔，**包括没问题的检查**，
避免来回返工，也避免「看起来应该好了」。格式跟 `TRACELOG.md` 一致。

**许可证**：Trilium 是 AGPL-3.0，用户已明确本项目也会开源，因此直接复用其

## [0] 真实数据的外部快照（改数据模型之前必须做的事）

`TRACELOG.md` 里记着两次事故：拿真实笔记跑自动化测试，**弄丢过两篇原文**，
两次都找不回来。当时的结论是——

> 必须有一份**独立于脚本自己运行状态的、外部的、只写一次的真原文快照**，
> 不能依赖「每个周期自己 backup-then-restore」这种自洽但没有外部锚点的机制。

这次改的是数据模型（文件夹变笔记、加 branches 表），比压测更有可能把数据搞
坏，所以先照做：

- `~/memoket-note-backups/20260910-192545/notes.sqlite3` —— 整库
- 同目录 `notes-markdown/` —— 42 篇导出成 markdown，**格式无关**，就算 sqlite
  schema 以后彻底变了，正文也还在
- 整个目录 `chmod a-w`，只写一次

**在仓库之外**，我后面的任何脚本都不会碰到它。

改前状态：notes 42（其中 6 篇正文为空，含 4 个由文件夹变来的）· folders 4 ·
branches 42 · writing_plans 49 · 迁移登记 `folders-into-tree-v1`。

## [1] 数据模型换成 Trilium 的 branches（已提交 6fe6b60）

**改了什么**：`notes` 表不再表达父子关系，树的边全在新的 `branches`
（note_id + parent_note_id + position）。一个笔记多条 branch = 克隆。
「文件夹」不再是一种东西，有子节点的笔记就是文件夹。

**迁移**：每个旧文件夹变成一篇空正文的笔记，**沿用原 id**，原来夹里的笔记
成为它的子节点。沿用 id 是有意的——`writing_plans.folder_id` 等外部引用不用
跟着改。

**测试**：新增 `tests/test_note_tree.py` 14 条；全量 690 条绿。两条防线各有
断言并反向验证过：最后一条 branch 不给摘、不许把节点移进自己的子树。

**路上的坑（值得记，差点白查一晚上）**：我给「看门狗被自己的日志弄死」写的
回归测试**自己把 pytest 干掉了**——它把 `os._exit` 换成记录函数并启动了看门狗
线程，而循环里 `os._exit` 之后没有 `return`；真实情况下那行不返回，被替换掉时
会返回，于是线程继续转。测试结束、monkeypatch 还原之后它拿到真的
`os._exit(0)`，**676 条只跑了 425 条就退出，退出码还是 0**，看起来像跑完了。
教训跟 TRACELOG 里那条同源：**测试环境比真实环境宽容，是这类 bug 的藏身处**。

## [2] 树的后端端点 + folders 删干净（第 1–15 轮）

**改了什么**
- 新增 `/api/tree`（整棵一次拿全）、`POST/DELETE /api/tree/branches`（克隆/
  摘除）、`PATCH .../move`、`PATCH .../expanded`、`GET /api/tree/paths/{id}`
- `create_note` 现在**同时挂树**——照 Trilium：笔记总是创建在某个父节点下，
  没有「建完再决定放哪」这个中间态。不挂就是一条用户看不见的垃圾数据
- `delete_note` 删**整棵子树**，返回被删的 id 列表；别处还有 branch 的克隆
  只摘边不删笔记
- `folders` 表、`notes.folder_id`、`routers/folders.py`、`tests/test_folders.py`
  **全删**；`writing_plans.folder_id` 改名 `parent_note_id`（值一个没动——
  迁移时旧文件夹沿用了原 id）
- 前端 `api.ts` 的四个文件夹函数换成六个树函数；`Folder` 类型删掉

**测试**：后端 682 绿（树 19 条 + 迁移 2 条）；前端 30 条 vitest 绿。
`test_folders.py` 里三条判据移植到了树上（按用户隔离、child_notes 的排除与
限量、以及**一个有意改掉的行为**：删文件夹从前保留里面的笔记，现在删子树）。

**踩的坑（这个文件自己警告过，我照样撞了）**
`_SCHEMA` 里加了一条引用新列名的索引 → 老库上 `CREATE TABLE IF NOT EXISTS`
是空操作，列还是旧名，索引当场 `no such column`。这个文件为 `idx_notes_folder`
写过一模一样的注释。索引已挪到迁移之后建。

## [3] 树控件 + 右键菜单 + harness 融入（第 41–60 轮，提前做）

**为什么提前**：`test_前端没有导出了谁都不用的东西` 抓到我写了四个树 API 却
没人用——右键菜单是它们唯一的使用者。与其挂着不如现在做。

**harness 怎么融入的**：直接长在树的右键菜单里——
「🤖 智能续写这篇 / ✨ 打磨这篇」对**一篇**，「🚀 对这棵子树无限续写」对
**一棵子树**，而树上本来就有这两个层级。禁用时带原因（「它只在这一个位置」
「它下面还没有笔记」），不是灰着不吭声。这是北极星判据 1 的直接落地：
一个按钮 + 一个可预期的结果。

**顺手修的真问题**：真库 18 篇有 15 篇标题字面就是「未命名」（旧界面建笔记
时的默认值），一列二十个「未命名」的树没法用。改成标题为空/占位时退回正文
首行——**只在显示层做，不写回库**：当成真标题存回去等于替用户起了名，而他
可能只是还没想好。

## [4] 两个自测设施（后面每一页都要用）

- `--user=`：Electron 新 profile 会造随机用户、看到空库，很容易误判成
  「数据没了」
- `--probe=`：右键菜单/弹层/分屏只有交互之后才存在，而发合成点击要系统
  「辅助访问」权限——不该为了自测让仓库主人去改系统设置。改成页面内探针，
  `?probe=tree-menu` 直接把界面驱动到那个状态。正常使用不带参数，那段代码
  一次都不执行

## [5] 六块外壳 + Trilium 令牌（第 16–40 轮）

启动栏 53px / 左栏 / 40px 标签行 / 中栏 / 右栏 / 状态栏，尺寸取自
`desktop_layout.tsx`（它自己写死的数字，不是我猜的）。

**主题只搬值不搬选择器**：`theme-next` 的 CSS 跟它自己的 DOM（`#root-widget`、
`.fancytree-*`、`body.layout-*`）绑得很死，整段搬过来会变成一堆永远不生效
的规则——那比不搬更糟，因为下一个人会以为主题已经在了。所以提取它的
**设计令牌**（亮暗两套配色值）写进 `shell.css`，再把老变量名指向这些令牌，
让整个应用一步吃到新配色。

状态栏放的是**当前在发生什么**（笔记数、harness 跑到哪、等你处置、后端
状态）——判据 3 要求自动化的过程看得见，一个只会转圈的指示器等于什么都没说。

## [6] 知识库：删掉问答框，能力封装成动作（第 96–115 轮，第一批）

**删了什么**：`MemoryPanel` 里那个「搜索或提问…」输入框 + 「提问」按钮。

**为什么**：判据 1——「界面上出现聊天输入框，就是我们没把意图封装好」。
但这里要分清一件事：**搜索不是聊天**。搜索框的结果是可预期的（匹配的记录），
而问答框要求用户自己组织 prompt，那才是要消灭的摩擦。所以搜索留着，
placeholder 从「搜索或提问…」改成「搜索知识库…」。

**能力没扔**：KITE 的时序推理恰好是痛点 13（汇总零散笔记时 AI 捋不清时间
线）的解药。新入口是**选中一段正文 → 右键「🕘 来龙去脉」**：

- 问题由后端 `/api/memory/trace` 拼，用户一个字都不写
- 结果落在右栏的「来龙去脉」标签里，**不是弹层**——判据 2：看一条旧记录
  不该离开这一页，弹层要么盖住正文、要么关掉就没了
- 每条事实可以一键插入正文（带 `[fact-id]`，为后面的行内出处 peek 铺路）
- `/api/memory/ask` 保留但 `include_in_schema=False`：它是 trace 和以后别的
  封装动作的底座，不再有对外入口

**测试**：`test_README里写的端点后端都有` 当场抓到 README 还写着
`/api/memory/ask`——契约测试正常工作。README 已同步（顺带补上笔记树那组
端点）。两端全绿。

## [7] 行内出处 peek（判据 2 最直接的落地）

正文里的 `[terrence-1872-5F8]` 变成可悬停的标记，浮层显示这条事实的原文 +
它的原始对话行。对标 Trilium 的 note peek / `openNoteInPopup`。

**为什么是浮层不是跳转**：跳走再回来，代价是那条思路（痛点 12）；浮层的
代价是「移开鼠标」，接近零。也直接对着痛点 13——汇总零散笔记时「有些事实
好像也不对」，事实旁边就是它的原话，对不对当场看得见，不用相信模型。

新增 `GET /api/memory/facts/{id}` 和 `UserMemory.fact_by_id()`。
**找不到明确 404**，不回空壳：一条指向不存在事实的引用是个真问题（模型编
的、或者知识库重建过 id 变了），静默当成没事等于把它藏起来。浮层里会说
「找不到这条记录——可能是引用写错了，或者知识库重建过」。

**实拍抓到的真问题**：第一版浮层几乎占满半屏。后端写了「最多三条原话」但
没限制单条长度，而一条会议记录原文能有几千字——浮层把正文盖住，反而违背了
判据 2（不打断当前这一页）。加了 220 字截断 + 换行压成空格，三条测试盯着。
**这个问题只有截图才看得出来**，测试和类型检查都是绿的。

出处识别的正则也有测试：认少了用户看不到出处，认多了正文里每个方括号都变成
点不开的假链接、还各打一次网络。写死「用户-数字-十六进制」三段形状，
`[2026-06]` 这种日期不会被误认。

## [8] 标签页（第 61–75 轮）

对标 Trilium 的 tab_row。尺寸取自它：单标签 100–240px，最窄 48px（再窄只剩
一个图标位、点不准），新建按钮 36px。中键关闭、⌘T/⌘W/⌘1–9（⌘9 是最后一个，
跟浏览器一致）。标签**持久化到 localStorage 按用户分**——关掉应用再打开桌面
还在，这是桌面应用的基本预期。

**为什么这个产品需要多标签**：痛点 10（笔记散在飞书和 Notion，想把两边交起来
写），以及写作时最常见的动作——对照着另一篇写。单篇编辑器逼着用户在脑子里
存住另一篇，那正是判据 2 要省下的注意力。

**两个 bug，都是截图才发现的**：

1. 我把 `setActiveTabId` 写在了 `setTabs` 的 updater 里面——而**这个文件在
   别处已经为同一件事写过警告**（liveContentRef 上面那段：「updater 必须是
   纯函数，在里面触发另一个 setState 是无效用法，React 19 StrictMode 还会
   双调用」）。实拍结果：连开三篇只出现一个标签。改成「哪个是当前」由一个
   effect 从 `current` 推导——一个真相，不用两处同步。

2. 探针的 effect 只依赖 `[tree]`，体内用的 `notes` 是旧闭包（那时还是空的），
   `notes.length >= 3` 静默跳过。修完才拍到三个标签。

两次都是 tsc 绿、测试绿，只有截图看得见。

## [9] 打包：装到没有 python 的机器上（第 126–140 轮）

**这是整件事里最后一个有真实失败风险的点**，所以做完就验。

- `backend/entry.py` + `backend.spec`：PyInstaller 把后端打成一个不依赖
  系统 python 的可执行程序（12MB 主程序 / 101MB 目录）
- `desktop/package.json` 的 electron-builder 配置把**前端和后端一起装进
  .app**（`extraResources`：web / backend）
- 打出 `MEMOKET NOTE-0.1.0-arm64.dmg`（181MB）

**验证方式不是「打包成功」，是真的跑打包产物**：

1. 先在 `env -i`（没有任何环境变量、没有 python）里跑冻结的后端——健康检查、
   首页、树接口全通
2. 再跑打包好的 .app——它自己拉起了**包内的**后端（
   `Contents/Resources/backend/memoket-note-backend`），接口全通

**实拍抓到的真 bug**：第一版打出来的 .app 是空库。查下去发现后端的
`kite_data_dir` 默认是相对路径 `./data`，打包后解析到了**.app 包内部**
（`Contents/Resources/backend/data/notes.sqlite3`）。这是个会丢数据的错：
macOS 的应用包在真实安装场景下只读，而且**更新时整个包会被替换，用户的
笔记跟着没**。

修法：Electron 用 `app.getPath('userData')` 把系统的用户数据目录经
`KITE_DATA_DIR` 传给后端，且只在 `app.isPackaged` 时传——开发时保持相对
`./data`，跟手工起后端用的是同一个库。重打包验证：数据落在
`~/Library/Application Support/memoket-note-desktop/data/`，**包内干净**。

七条回归测试盯着这些约定（`tests/test_packaging.py`）——它们不是「代码对不
对」，是「装到别人机器上会不会出事」，而那件事只有真打一次包才看得见。

## [10] 笔记 × 知识库：双向链接落地（第 141–150 轮）

设计见 `docs/kb-fusion-design.md`。这一批做的是骨干——**引用关系变成数据**，
而不只是正文里的一串字：

- `note_citations` 表随每次保存重建（`store.sync_citations`），树接口带
  `cite_count` / `ingested_at` / `preview`，左栏节点上直接看 ◆N 和 ⇡
- 摄入是后台任务：`_ingest_job` 结束时 `mark_ingested`，前端 `watchJob`
  结束刷树——不刷的话 ⇡ 要下次开应用才出现，用户会以为没存上、再存一遍
- ribbon 新增「知识库」标签（`NoteKbPanel`）：引用了哪几条、摄入状态、
  **找不到的引用**用红色报出来（模型编的、或者知识库重建过 id 变了——
  藏起来等于让一篇笔记建立在不存在的依据上）、每条依据「也引用于」哪几篇
- 反查端点 `GET /api/memory/facts/{id}` 与 `/citing`

**实拍抓到的问题**：`--probe=kb-tab` 往正文塞的两条假引用被 1.5s 自动保存
落进了真实笔记，连拍三次就多了三行「据 […] 所述」。修法：probe 模式下不
自动保存；顺手把已经污染的那篇清干净（sqlite 直接改，改前查过只有一篇）。

另一个小教训：假引用写成 `[terrence-9999-ZZZ]`，`ZZZ` 不是十六进制，正则
根本不认——所以「找不到」那条红提示这次没拍到。下一批换成
`[terrence-9999-FFF]` 再拍。

测试：后端 703 通过（+11 `test_kb_fusion.py`），前端 tsc + vitest + 11 条
check 脚本全绿。

## [11] Trilium 比对报告第一批：现在就是坏的六条（第 151–160 轮）

比对报告在 `docs/trilium-ui-gap.md`（11 严重 / 39 明显 / 58 细节，每条带
Trilium 的 `文件:行号`）。第一批按「现在会不会坏」排，不按好看程度：

1. **左栏没有滚动容器**——树塞在 `.left-pane-search` 里、外层 `overflow:hidden`，
   笔记一多底部被裁掉且滚不到。`.left-pane-body` 早就写好了但 0 处引用。接上。
2. **标签行溢出不可达**——一路缩到 48px 后再多就点不到。改成 strip 横向可滚
   （滚轮竖转横、不显滚动条）、下限 84px、间隙 5px；新建按钮挪出 strip；
   末尾 50px filler 做拖动区。
3. **`--bg` 语义倒置**——错指到 `--accented-bg`（Trilium 的「抬升面」，暗色
   `#555`），暗色下页面底比卡片还亮，遮罩是一块不透明中灰。改指 `--main-bg`，
   另立 `--surface-raised` / `--hover` / `--backdrop-color` / `--shadow-opacity` /
   `--accent-fg` / `--warn` / `--card-alt` / `--focus-ring`。后四个里有两个原来
   是**从未定义的幽灵变量**（`--card-alt` 被引 4 次），代码块底色一直不跟主题。
4. **`data-theme` 半坏**——shell.css 有 `:not([data-theme="light"])` 守卫，
   styles.css 是裸 `:root`，没有代码写过它。删掉守卫，两边一致只看系统偏好。
5. **红绿灯压住左栏**——`hiddenInset` 下只在 58px 宽的启动栏顶部留了 22px，
   红绿灯横向约 70px。照 Trilium 的处理：标签行提到最顶、整行宽，左端 72px
   spacer（仅 macOS，`html.is-mac`）。
6. **写作骨架 ribbon 永远默认收起**——直接违反判据 3。照 `Ribbon.tsx:46-51`
   加 `activate` 规则：换笔记时取第一个 activate 为真的 tab 展开。骨架有节拍、
   或正文有引用时自动展开。

顺手：尺寸抄**跑起来的** Trilium（theme-next 用 `!important` 盖掉了
desktop_layout.tsx 的 53/40）：启动栏 58、标签行 50、标签 36 全圆角 8 +
激活阴影、状态栏 28 走左栏色；树激活态换成「浮起来的卡片」（那四个
`--left-pane-item-*` 令牌抄来了从没接上）；标题行提出滚动区固定 50px；
标签名走共享的 `displayTitle`（三个「未命名」标签现在各叫各的名）；
`:focus-visible` 焦点环（此前全仓一条都没有）。

实拍：亮/暗各一张（`--dark` 标志强制 nativeTheme，不用去系统设置切）。
暗色层级终于是对的。

## [14] 第五批：特殊笔记、导入子树、收尾杂项（第 211–235 轮）

  只给看不见后果的动作用。

- 右栏「浏览」改成打开「总览」标签（`open-virtual` 窗口事件），弹层版
  MemoryBrowser 不再有入口。
- 应用图标：PIL 画 1024 → iconset → `iconutil` → icns；electron-builder `mac.icon`。

**实拍抓到的**：

## [15] 分屏、自截图、以及一条真正的融合缺口：续写从来不带引用（第 236–255 轮）

- **分屏**：中栏右侧第二栏（Trilium SplitNoteContainer），树菜单 / 标签菜单 /
  ribbon ⋯ 三处入口，可拖宽、持久化。**第二栏是只读的**——「对照着另一篇写」
  要的是看得见，不是两个光标；编辑器状态是单实例的，做成可编辑要重构一半的
  App.tsx。虚拟节点也能进分屏（在分屏里看一条事实，「引用到笔记」直接插到
  左边正在写的那篇）。
- **`--shot=path` 自截图**：`webContents.capturePage` 存 PNG 后退出。这次
  `screencapture` 连拍三次都是桌面壁纸——窗口没在前台、`osascript` 没有辅助
  功能权限。自己截自己不依赖这些。
- **一条真缺口**：三条「找到并引用」的路径（@ 补全 / 相关记忆 / ⌘K）插的是
  `[事实：文字 · 日期]`，而后端 `store.cited_fact_ids` 只认 `[user-n-hex]`——
  于是用户手动引用的从来没算成引用（树上 ◆N 不涨、peek 不认、反向链接查不到）。
  更大的那半：**harness 续写的产出也从来不带引用**——喂给模型的材料是
  `[日期] 正文`，没有 id，模型想引也引不了。修法：
  1. `retrieval.format_fact` 输出 `[id] [日期] 正文`（跟 agent 工具输出同形）
  2. `facts_block` 在材料带 id 时讲引用规则（「句末原样照抄 [编号]」）
  3. 新判据 `citations_exist`：正文里的 `[id]` 要么在材料里、要么知识库里查
     得到，否则是编的——**可自动修**（摘掉那个 `[id]`，正文不动）。接进
     单篇和分段两条 harness
  4. 三条前端路径统一插 `原文 [id]`
- **收紧引用正则**：`[2026-01-01]` 也匹配旧正则（`01` 是合法十六进制）——
  判据会把正文里的日期当编造引用摘掉。用户名段必须以字母开头。**五处同步**
  （store / checks / fragments / factCite.ts / App.tsx），各自有测试。

测试：后端 730 通过（+9），前端 vitest +1。`test_harness_modes` 那段「踩满
所有毛病的正文」补了一个编造的 `[u-999-FF]`——否则新判据在那条「每条判据
至少触发一次」的断言下是空转的。

**真跑验证**（不靠测试靠产出）：起后端，对 terrence 的库调一次
`POST /api/magic-tap`（spine「众筹节奏要跟版本节点对齐」）。meta 里 6 条材料
都带 id；产出 298 字，**三处引用都是真的**：`[terrence-1872-5F8]`
「2.0 版本的时间先放 6 月 30」、`[terrence-1238-3F2]`「1.0 版本一个月补全」、
`[terrence-1462-1F8]`「众筹 plan 对齐」。存进笔记后树上会直接显示 ◆3、悬停
看出处、事实页反查得到这篇——整条「AI 写的每一句都有据可依」的链路第一次
端到端通了。
